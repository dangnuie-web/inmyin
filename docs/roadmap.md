# 작업 순서 

체크박스 하나가 한 작업 단위다. 위에서부터 하나씩 끝내고, 끝낼 때마다 체크한다.

클로드 코드에게 어떻게 말할지는 `docs/how-to-ask.md`에 문장이 그대로 적혀 있다.

## 0단계 — 준비

**본인이 직접 해야 하는 것** (계정 만들기라 대신 못 함)

- [✅] GitHub 계정 만들기
- [✅] Supabase 계정 만들고 프로젝트 하나 생성
- [✅] Vercel 계정 만들기 (GitHub으로 로그인하면 편함)

**클로드 코드에게 시킬 것**

- [✅] Next.js + TypeScript + Tailwind 프로젝트 생성
- [✅] GitHub 리포지토리 연결 + 첫 커밋
- [✅] Supabase 연결 (환경변수 설정)
- [✅] `docs/data-model.md`의 테이블 생성 + RLS 정책
- [✅] `lib/plans.ts`, `lib/categories.ts` 상수 작성
- [✅] 피그마에서 옮긴 색·타이포·여백을 Tailwind 토큰으로 등록
- [✅] 빈 화면 하나 배포해서 Vercel 주소 확인 — https://inmyin.vercel.app

마지막 항목까지 하면 인터넷 주소가 하나 생깁니다. 내용은 없어도 괜찮아요. **한 번 배포해두면 그 뒤로는 코드만 고치면 자동으로 갱신됩니다.**

## 1단계 — 혼자서 쓸 수 있는 앱 (MVP)

커뮤니티를 다 빼고 내 물건을 넣는 것까지만. 이것만 돼도 매일 쓴다.

- [✅] 소셜 로그인(구글·카카오) + 이메일 가입
- [✅] 비밀번호 재설정 (A-04) — A-01a의 "비밀번호를 잊으셨나요?"
- [✅] 하단 탭 뼈대 (Home · My · Like) — Home과 Like는 빈 화면
- [✅] 인벤토리 목록과 생성 (M-03) — 사진 업로드 + 이름 + 카테고리 태그. 추천 4종은 글자를 채워주는 지름길
- [✅] 인벤토리 상세 격자 (M-04) — 헤더 · 인벤토리 띠 · 그리드/리스트 토글 · 25칸 격자 · + 칸과 플로팅 + · 두 갈래 메뉴. 아이템이 없어도 볼 수 있는 틀까지
- [✅] 아이템 등록 ① 정보 입력 + 사진 업로드 → 칸에 배치 (M-08) — 저장하면 그 칸으로 스크롤 + 1초 강조. 여기서부터 실제로 물건을 넣어볼 수 있다
- [✅] 아이템 등록 ② 촬영 화면 (M-06) — 프레임 안쪽은 썸네일, 찍힌 전체는 원본. 인벤토리의 "사진 찍기"도 같은 화면
- [✅] 아이템 등록 ③ 편집 — 배경제거 (M-07). 인벤토리 생성에도 끼웠다. 글쓰기 · 그리기는 뺐다 (아래 "나중에 할 일")
- [✅] 아이템 상세 (M-14) — 칸을 누르면 큰 사진 · 이름 · 설명 · 날짜. 아래에 같은 인벤토리의 칸들. 헤더의 ⋮ 메뉴는 틀만
- [✅] 아이템 수정 · 삭제 — 리스트는 밀어서, 그리드는 길게 눌러서 + M-14 의 ⋮ 메뉴. 삭제는 바로 지우고, 지운 자리가 5초 동안 "되돌리기" 칸으로 남는다. 수정은 글자 정보만 (사진 바꾸기는 나중에 할 일)
- [✅] 인벤토리 줄 밀어서 수정 · 삭제 (M-03) — 인벤토리는 비어 있을 때만 삭제. 수정은 이름과 태그만. 없앤 태그는 아이템에서도 뗀다
- [✅] 짐싸기 (M-05) — 혼자 쓰는 기능이라 1단계에 넣는다
- [✅] 인벤토리 안에 인벤토리 담기 — + 메뉴의 "인벤토리 가져오기"(아래에서 올라오는 목록), 길게 눌러 "꺼내기", 짐싸기(M-05)에서 담긴 인벤토리 옮기기. 담긴 인벤토리를 지웠다 되살리면 원래 순서로 돌아가게 DB 규칙도 고쳤다
- [✅] 내 프로필 (M-01), 설정 (M-02) — 설정 아래의 로그인 정보 · 오픈소스 라이선스까지. 아직 없는 기능의 버튼은 자리만 잡고 "곧 만들어요"를 띄운다
- [✅] 프로필 관리 — 프로필 사진 · 닉네임 · 아이디 수정. 디자인이 없어서 다른 정보 입력 화면(M-08)과 같은 모양으로 만들었다
- [✅] 아이템 모아보기 (M-13) — 검색 · 카테고리 칩 · 그리드/리스트. 카테고리 칩을 한 줄로 쓸어 넘기는 공용 부품(ChipRow)을 만들어 M-04 에도 넣었다
- [✅] PWA 설정 — manifest(`app/manifest.ts`) + 서비스워커(`app/sw.ts`, Serwist Turbopack) + 아이콘(`public/icons/`). 아이폰 전용 태그는 `app/layout.tsx`. 인터넷이 끊기면 마지막으로 본 화면을 다시 보여주고, 없으면 `/offline`. Supabase · 배경제거 모델 · 로그인 콜백은 저장하지 않는다. 개발 중(`npm run dev`)에는 서비스워커를 끈다 — 확인은 `npm run build && npm start`
  - 앱 아이콘은 `inmyin logo_2.svg`(시안 3번)로 정했다. 바꾸려면 `npm run app-icon -- "<svg 경로>"` 로 아이콘 4종과 favicon 을 다시 만든다
  - 아이콘 시안 고르기 도구는 INMYIN 밖으로 뺐다 — 옆 폴더 `../icon-preview` (GitHub `dangnuie-web/icon-preview`, 배포 https://icon-preview-dangdang3.vercel.app). 시안을 아이폰 홈 화면 모양에 넣어 보고 "홈 화면에 추가"로 진짜 아이콘으로 깔아 볼 수 있다. 다른 프로젝트에서도 쓴다 — 쓰는 법은 그 폴더의 README

### 내 아이폰에 설치해보기

1단계가 끝나면 바로 해보세요. 여기서 만든 게 손에 잡힙니다.

- [✅] Vercel에 배포
- [✅] 아이폰 **사파리**로 접속 (크롬 아님)
- [✅] 하단 공유 버튼 → **홈 화면에 추가**
- [✅] 홈 화면 아이콘으로 열어서 주소창 없이 뜨는지 확인
- [✅] 실제로 물건 20개쯤 넣어보기

**앱스토어는 지금 필요 없습니다.** 자세한 이유는 `docs/for-beginners.md`.

20개를 넣어보면 기획에서 안 보이던 게 보입니다. 거기서 나온 불편함을 먼저 고치고 2단계로 가세요.

## 2단계 — 보여주기

- [✅] 공개/비공개 처리 — 아이템 토글은 이미 있었고, 인벤토리에도 공개 토글을 넣었다 (끄면 안의 것까지 통째로 숨는다). 남이 읽을 때는 DB 규칙(RLS + `inventory_visible`)이 막아서, 어떤 화면을 만들어도 비공개 것이 새지 않는다. 남의 것을 "공개만 모아 다시 줄 세워" 보여주는 조회 함수는 그걸 쓰는 화면(H-01 · H-06~08)을 만들 때 같이 만든다
- [✅] Home › 아이템 피드 + 검색 + 카테고리 필터 (H-01, H-02) — 모든 사람의 공개 아이템 최신순, 검색 · 카테고리는 주소로 서버가 거른다, "더 보기"로 60개씩. 남의 아이템 상세는 같은 `/items/[id]` 에서 ⋮ 대신 작성자 줄. **확인하려면 다른 계정(dangnee2)으로 아이템을 하나 올리고 dangnee 로 Home 에서 열어 본다** — 지금은 공개 아이템이 전부 dangnee 것이라 남의 상세 화면을 아직 실제로 못 봤다
- [✅] 좋아요 (아이템·게시물 공용) — H-02 제목 줄의 하트. 누르면 화면부터 바뀌고 서버에 저장, 수는 DB 트리거가 센다. `setLike(targetType, targetId, liked)` 한 동작을 아이템 · 게시물이 같이 쓴다. 좋아요한 것을 모아 보는 Like 탭은 아래 항목
- [✅] 팔로우 / 팔로잉·팔로워 목록 (M-12) — H-02 작성자 줄의 팔로우 버튼, 프로필 숫자 → 목록 화면 `/u/[아이디]/follows`. 모달(M-12a)은 만들지 않고 화면으로 간다
- [ ] 타유저 프로필 (H-06~H-08) — 비공개 아이템 숨김 처리 포함
- [ ] Like 탭 (V-01, V-02) — 검색·카테고리 필터 포함
- [ ] 차단
- [ ] 웹(데스크톱) 레이아웃 — 프로필+인벤토리 한 화면, 등록 버튼 자리에 안내

여기까지 하면 친구에게 링크를 보낼 수 있습니다.

## 나중에 할 일

단계와 상관없이 미뤄 둔 것들. 끝내면 체크한다.

- [✅] **배경제거 라이브러리의 라이선스 정하기** — `@imgly/background-removal` 이 AGPL-3.0 이라 ① 소스코드 공개를 골랐다. GitHub 저장소를 공개로 바꾸고 `LICENSE`(AGPL-3.0) · README · 설정 › 오픈소스 라이선스에 소스코드 링크를 넣었다. 다른 길이었던 ② IMG.LY 상용 라이선스 ③ 다른 모델 · 외부 API 로 갈아타기는 아래 항목으로 남긴다
- [ ] 배경제거를 라이선스가 자유로운 모델로 갈아타는 실험 — MODNet · U²-Net 같은 Apache/MIT 모델을 `lib/background-removal.ts` 한 파일만 바꿔 폰에서 돌려 보고 누끼 품질을 지금 것과 비교한다. 품질이 괜찮으면 갈아타고, 그 뒤에는 저장소를 다시 비공개로 돌릴 수 있다 (AGPL 코드를 뺀 뒤라면 가능). 외부 API(remove.bg · Photoroom)는 장당 돈이 들고 사진이 폰 밖으로 나가서 후순위
- [ ] 이용약관 · 개인정보처리방침 초안의 법률 검토 — 초안은 클로드가 썼고 법률 자문이 아니다. 유료 서비스(4단계)를 열기 전에 전문가에게 한 번 보인다
- [ ] 계정 전환 — 인스타처럼 계정 둘 이상을 담아 두고 한 번에 바꾸기. 세션을 여러 개 안전하게 보관해야 해서 큰 일이다. 지금은 로그아웃 → 다른 방식으로 로그인 (dangnee = 이메일, dangnee2 = 카카오)
- [ ] 피그마 정리 — 화면 여백 20px 규칙 반영, H-02 프레임의 북마크 아이콘 지우기 (북마크는 없다) — 코드는 다 맞췄지만 피그마 프레임은 아직 화면별 값(25 · 28 · 44px 등)이다
- [ ] 배경을 지우는 동안의 로딩 애니메이션 (M-07) — 지금은 "배경을 지우는 중…" 글자와 깜빡임뿐이다. 처음 한 번은 20초쯤 걸리는 순간이라 기다릴 만하게 만든다. 누끼가 "사삭" 따지는 연출도 여기서
- [✅] **이용약관 · 개인정보처리방침의 글 준비하기** — 초안을 `lib/policies.ts` 에 쓰고 `/terms` · `/privacy` 로 연다 (로그인 없이). 가입 동의 항목의 "보기", 로그인 화면 아래, 설정(M-02)에서 링크. 글을 고치면 `updatedAt` 도 고친다. 법률 검토는 아래 항목
- [ ] 설정 › 알림 — 4단계의 유통기한 임박 알림 · 푸시 알림과 함께
- [ ] 아이템 · 인벤토리 수정에서 사진 바꾸기 — 지금은 글자 정보만 고친다 (인벤토리 수정 화면은 사진을 보여주기만 한다). 사진을 바꾸려면 촬영 → 편집을 다시 거쳐야 해서 따로 붙인다
- [ ] **사진 편집(M-07)에 색 보정(레벨 조정) 넣기 — 글쓰기 · 그리기보다 이쪽이 먼저다.**
  - 왜: 어두운 곳에서 찍으면 색이 틀어진다 — 노란 물건이 녹색으로 찍힌다. 이 앱은 "내 물건을 알아보는 것"이 핵심이라, 사진의 색이 실물과 다르면 곤란하다. 꾸미기(글씨 · 낙서)보다 **실물처럼 보이게 고치는 것**이 등록 단계에 더 필요하다
  - 무엇을: 밝기 · 대비 · 색온도(화이트밸런스: 노랗게 ↔ 파랗게) · 색조(녹색 ↔ 자주색) 정도. 노랑이 녹색이 되는 문제는 색온도와 색조로 잡는다
  - 어떻게(후보): ① 한 번 누르면 알아서 맞춰 주는 **자동 보정** 버튼을 먼저 — 등록은 빨라야 한다 ② 그걸로 부족하면 직접 미는 슬라이더. 브라우저의 캔버스로 직접 계산할 수 있어서 새 라이브러리는 필요 없을 가능성이 크다 (만들 때 확인)
  - 어디에: M-07 오른쪽 위의 버튼 줄. 피그마에서 텍스트 · 그리기 버튼이 있던 자리 (배경제거 아래)
  - 지킬 것: 보정은 썸네일에만 입힌다. 원본은 찍힌 그대로 보관한다 (CLAUDE.md 규칙 7) — 나중에 더 나은 보정으로 다시 만들 수 있어야 한다. 배경제거와 어느 쪽을 먼저 할지(보정 → 누끼 순서가 누끼 품질에 유리할 수 있다)는 만들 때 실험해 정한다
  - 촬영 화면(M-06)에서 미리 막는 방법(어두우면 "밝은 곳에서 찍어 주세요" 안내, 플래시 버튼)도 같이 검토한다
- [ ] 사진 편집(M-07)에 글쓰기 · 그리기를 넣을지 다시 정하기 — 지금은 뺐다. 등록이 빨라야 하고, 꾸미는 일은 INMYIN 에디터(M-09)가 맡는다. 주인의 생각은 "그리기 · 텍스트보다는 색 보정" (위 항목)

## 클로드 코드에 일을 시킬 때

"앱 만들어줘"는 잘 안 된다. 위 체크박스 하나를 그대로 주는 게 가장 잘 된다.

```
docs/screens.md의 M-04(인벤토리 상세)를 만들어줘.
25칸 격자, 빈 칸 탭하면 두 갈래 선택.
CLAUDE.md의 규칙 1번(아이템은 불러올 수 없음)을 지킬 것.
```
