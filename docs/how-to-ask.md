# 클로드 코드에게 일 시키는 법

이 파일은 사람이 읽는 사용설명서입니다. 여기 있는 문장을 복사해서 그대로 쓰세요.

## 기본 원칙 네 가지

**① 한 번에 하나만 시킨다**

"앱 만들어줘"는 실패합니다. `docs/roadmap.md`의 체크박스 하나가 한 번에 시킬 분량이에요.

**② 어느 문서를 보라고 알려준다**

클로드 코드는 폴더 안 파일을 읽을 수 있지만, 알아서 다 읽지는 않습니다. "`docs/screens.md`의 M-04를 읽고"처럼 짚어주면 훨씬 정확해집니다.

**③ 다 만든 뒤에 확인하지 말고, 중간에 확인한다**

"만들기 전에 어떻게 만들 건지 먼저 설명해줘"를 붙이세요. 방향이 틀렸을 때 코드를 다 버리지 않아도 됩니다.

**④ 안 되면 화면을 보여준다**

에러 메시지나 화면 스크린샷을 그대로 붙여넣는 게 말로 설명하는 것보다 빠릅니다.

---

## 맨 처음 (프로젝트 시작할 때)

터미널에서 빈 폴더를 만들고, 그 안에 `CLAUDE.md`와 `docs/` 폴더를 넣은 뒤 클로드 코드를 실행하세요.

```
이 폴더의 CLAUDE.md와 docs/ 안의 문서를 전부 읽어줘.
다 읽고 나서, 네가 이해한 걸 열 줄 이내로 요약해줘.
아직 코드는 만들지 마.
```

요약이 엉뚱하면 문서가 부족한 겁니다. 그 부분을 저한테 알려주시면 문서를 고쳐드릴게요.

---

## 0단계 — 준비

```
docs/roadmap.md의 0단계를 시작하자.
Next.js + TypeScript + Tailwind로 프로젝트를 만들어줘.
만들기 전에, 어떤 명령어를 쓸 건지와 왜 그런지 먼저 설명해줘.
내가 확인하면 그때 실행해.
```

Supabase는 계정을 직접 만들어야 하니 이렇게 물어보세요.

```
Supabase를 연결하려고 해. 나는 개발이 처음이야.
내가 Supabase 사이트에서 직접 해야 하는 일과,
네가 코드에서 할 일을 나눠서 알려줘.
내가 해야 하는 건 클릭 순서까지 알려줘.
```

테이블 만들기.

```
docs/data-model.md를 읽고 Supabase에 테이블을 만드는 SQL을 써줘.
RLS 정책도 같이. "내 데이터는 나만 수정할 수 있다"가 기본이야.
SQL을 실행하기 전에, 각 테이블이 무슨 역할인지 한 줄씩 설명해줘.
```

## 1단계 — 화면 만들기

화면 하나를 시킬 때의 기본 틀입니다.

```
docs/screens.md의 M-04(인벤토리 상세)를 만들어줘.

지켜야 할 것:
- CLAUDE.md의 규칙 1번 (아이템은 불러올 수 없음)
- 25칸 격자, 빈 칸 탭하면 두 갈래 선택
- 새 아이템은 마지막 빈 칸에 들어감

만들기 전에 어떤 파일을 새로 만들고 어떤 걸 고칠 건지 먼저 알려줘.
```

디자인을 맞출 때.

```
피그마 파일을 보고 색이랑 여백을 Tailwind 설정에 옮겨줘.
피그마 링크: (여기에 링크)
변수 이름은 피그마에 붙여둔 그대로 써줘.
```

> 피그마 링크를 줄 때는 **보기 권한 + Dev Mode 접근**을 켜두세요. 안 켜져 있으면 클로드 코드가 못 읽습니다.

## 막혔을 때

**에러가 났을 때**

```
이 에러가 났어. 원인이 뭐고 어떻게 고치는지 알려줘.
고치기 전에 왜 이런 일이 생겼는지 설명해줘.

(에러 메시지 붙여넣기)
```

**화면이 이상할 때**

```
(스크린샷 붙여넣기)
이렇게 나오는데 내가 의도한 건 docs/screens.md의 M-04야.
뭐가 다른지 짚어주고 고쳐줘.
```

**코드가 이해가 안 될 때** — 이걸 자주 쓰세요. 바이브 코딩에서 제일 중요한 습관입니다.

```
방금 만든 파일을 한 줄씩 설명해줘.
나는 개발이 처음이니까 용어가 나오면 그 자리에서 풀어서 써줘.
```

**방향이 틀렸을 때**

```
잠깐, 이건 내가 원한 게 아니야.
방금 바꾼 걸 되돌리고, 다시 시작하기 전에 계획부터 말해줘.
```
