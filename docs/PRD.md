# INMYIN — 제품 정의

## 한 줄

내가 가진 것을 사진으로 찍어 가상의 창고에 넣어두고, 한눈에 보고 남에게 보여주는 앱.

## 왜

물건을 격자 칸에 채워 넣는 게임 인벤토리의 은유를 그대로 쓴다. 등록은 사진 한 장에서 시작하고, 배경을 자동으로 지워 물건만 남긴 썸네일이 칸에 꽂힌다. 모인 아이템은 혼자 관리용으로 쓸 수도, 공개해서 다른 사람에게 보여줄 수도 있다.

## 누가 언제 쓰는가

| 상황 | 쓰는 방식 | 중요한 기능 |
| --- | --- | --- |
| 취향 공유 | 좋아하는 물건을 공개 인벤토리에 모아 친구에게 보여줌 | INMYIN 게시물, 팔로우, 프로필 공유 |
| 물건 관리 | 내가 가진 것을 한눈에 보고 중복 구매를 막음 | 인벤토리 그리드, 카테고리, 개수 |
| 이사 | 짐을 상자 단위로 기록해 어디에 뭐가 들었는지 추적 | 인벤토리 중첩, 짐싸기 |
| 냉장고·옷장 | 재료와 옷을 찍어두고 보유 현황 확인 | 유통기한, 획득날짜 필드 |

주 사용자는 정리와 기록을 좋아하고, 자기 취향을 남에게 보여주는 데 거리낌이 없는 사람이다. 대화보다는 **보여주기와 구경하기** 중심의 느슨한 커뮤니티다 — 처음엔 댓글 없이 좋아요와 팔로우만 두었는데, 친구와 써 보니 반응(하트) · 모으기(북마크) · 짧은 댓글 · 알림 정도는 있어야 서로 쓰는 맛이 나서 2.5단계에서 더했다.

## 확정된 규칙

| 항목 | 결정 |
| --- | --- |
| 앱 이름 | INMYIN |
| 인벤토리 확장 | 결제. 베이직 / 프리미엄 2단계 |
| 로그인 | 구글·카카오 간편로그인 + 이메일 가입 모두 |
| 카테고리 | 인벤토리마다 유저가 정하는 자유 태그. 추천 4종은 이름과 기본 태그를 채워주는 지름길일 뿐이다 |
| 비공개 아이템 | 남이 볼 때 아예 안 보인다 (칸째로 빠짐) |
| 비공개 인벤토리 | 남이 볼 때 아예 없는 것처럼 보인다. 안의 아이템은 공개로 되어 있어도, 안에 담긴 인벤토리도 같이 숨는다 (겉이 숨으면 속도 숨는다). DB 규칙(`inventory_visible`)이 막는다 |
| 인기 순위 | 북마크 수 + 시간 창. 인기 / 추천 두 필터로 분리 (하트는 세지 않는다) |
| 데스크톱 | 촬영만 불가. 아이템 · 인벤토리 사진은 업로드로 넣는다. 기능은 폰과 같고 레이아웃만 넓다 (상단 메뉴 · 930px · 7칸 격자). 팔로워 목록만 웹은 모달, 폰은 화면 |
| 신고·차단 | 차단은 2단계에 만들었다 — 서로의 아이템 · 인벤토리가 양쪽 다 안 보이고 팔로우가 끊긴다. 신고는 추후 과제 |
| 짐싸기 | 다중 선택 없음, 되돌리기 없음. 받는 쪽이 꽉 차면 알림 |
| 아이템 재사용 | 아이템은 불러올 수 없다. 인벤토리는 다른 인벤토리에 담을 수 있다 (한 줄로 5겹까지. 예: 집 › 방 › 가방 › 작은 가방 › 파우치) |
| 칸 배치 | 새 아이템은 항상 마지막 아이템의 다음 칸. 기존 아이템을 밀어내지 않는다. 중간이 비면 뒤의 것들이 한 칸씩 당겨 붙는다 |
| 수정 · 삭제 | 밀기 동작. 왼쪽으로 밀면 삭제, 오른쪽으로 밀면 수정. 아이템(그리드 · 리스트)과 인벤토리 줄 모두 같다 |
| 백엔드 방식 | Supabase 클라이언트로 직접. GraphQL·별도 API 서버 없음 |
| 배포 | PWA 우선. 앱스토어는 나중에 (아래 배포 계획) |
| 유통기한 알림 | 추후 과제 (설정 › 알림) |
| 삭제된 아이템 | 게시물 이미지는 남고 링크만 죽는다 |
| 이미지 보관 | 원본 + 배경제거본 둘 다 |

## 추천 인벤토리와 카테고리

카테고리는 **인벤토리마다 유저가 정하는 자유 태그**다. 인벤토리에 저장된다 (`Inventory.categories`).

추천 4종은 `lib/categories.ts`에 상수로 둔다. 인벤토리를 만들 때 이름 칸의 드롭다운에 나오고, 고르면 이름과 기본 태그가 채워진다. **글자를 채워주는 지름길일 뿐이다** — 채워진 뒤에는 이름을 고쳐도, 태그를 지우거나 직접 추가해도 된다. 아무것도 고르지 않고 처음부터 직접 써도 된다. 저장된 뒤에는 추천에서 온 것과 직접 쓴 것을 구분하지 않는다. 인벤토리에 "종류"라는 개념은 없다.

| 추천 이름 | 기본 태그 |
| --- | --- |
| 옷장 | 상의, 하의, 신발, 모자, 가방 |
| 냉장고 | 육류, 야채, 반찬, 냉동, 조미료 |
| 집 | 거실, 침실, 화장실 |
| 생활용품 | 청소, 세탁, 소모품 |

- 태그는 인벤토리당 10개, 한 개에 10자까지. 같은 태그를 두 번 달 수 없다
- 아이템은 자기 인벤토리의 태그 중 하나를 탭으로 고른다. 고르지 않아도 된다
- 인벤토리에서 태그를 지워도 이미 그 태그를 단 아이템은 그대로 둔다. 새로 고를 때만 목록에서 빠진다
- 짐싸기로 옮긴 아이템의 태그는 그대로 따라간다
- 카테고리 칩을 보여주는 곳은 **맨 앞에 항상 "전체"**를 둔다. 태그가 없는 아이템은 "기타" 같은 칩을 따로 만들지 않고 **"전체"에서만** 보인다

## 인기와 추천 산식

`lib/ranking.ts`.

| 필터 | 대상 | 정렬 |
| --- | --- | --- |
| 인기 | 전체 유저 | 최근 24시간 북마크 수 |
| 추천 | 누적 북마크 100 미만인 유저 | 최근 1시간 북마크 수 |

기준선 100은 상수로 빼둔다. 사람이 모이면 조정한다.

## 배포 계획

| 단계 | 방식 | 비용 | 언제 |
| --- | --- | --- | --- |
| 1 | Vercel 배포 + 사파리 "홈 화면에 추가" | 무료 | 1단계 끝나면 바로 |
| 2 | 같은 링크를 친구에게 공유 | 무료 | 2단계 끝나면 |
| 3 | Capacitor로 감싸서 앱스토어 | 연 99달러 | 사람이 붙고 푸시가 꼭 필요해지면 |

**앱스토어는 처음부터 고려하지 않는다.** 웹을 그대로 감싸 올리면 애플 심사 지침 4.2(minimum functionality)로 반려되는 경우가 많고, 지금 단계에서 얻을 게 없다. 지금 코드를 그대로 쓰면서 나중에 감쌀 수 있으니 미루면 된다.

### iOS PWA 제약 (기획 시 감안할 것)

- 설치는 사파리 "홈 화면에 추가"로만 된다. 안드로이드처럼 설치 배너가 뜨지 않으므로, 설치 안내 화면을 따로 만들어야 한다
- 푸시 알림은 iOS 16.4 이상 + 홈 화면에 설치된 상태에서만 온다
- 카메라는 동작하지만 기본 카메라 앱만큼 매끄럽지 않다
- 앱스토어 검색으로는 찾을 수 없다. 초기 유입은 링크 공유뿐이다

## 아직 정해지지 않은 것

- 프리미엄 가격과 결제 수단
- Home · Bookmark 의 카테고리 필터 방식 — 태그가 자유라서 고정 2단 칩(옷장 › 상의)은 쓸 수 없다. 2단계에서 "검색 + 많이 쓰이는 태그 칩" 방향으로 정한다
- PWA 설치 안내를 어느 화면에서 어떻게 띄울지
