# 화면 정의

피그마 파일 `인벤토리` 기준. 고유 화면 32개 (알림 N-01 은 피그마 없이 만들었다). 모바일 프레임이 기준이고, 같은 화면의 웹(데스크톱) 버전이 별도 프레임으로 존재한다.

## 하단 탭

```
1. 홈   2. 발견   3. + (촬영)   4. 북마크   5. 프로필
```

2026-10-20 당니님 결정(무늬 설계서 `화면손질설계_v01` 2절 A안)으로 피그마의 셋(Bookmark · Home · My, Home 가운데)에서 다섯으로 바뀌었다. 홈이 맨 왼쪽, 가운데는 촬영 + — 검정 원 40, 라벨 없음(`aria-label` "아이템 촬영"). 이름은 한글. 아이콘 24px · 라벨 11px, 막대 위에 1px 회색 선. 선택된 탭은 아이콘 속을 채우고(집 문 · 나침반 바늘은 구멍), 글자는 그대로 둔다. 아이콘은 무늬가 로고의 n 아치로 직접 그린 세트 v01 (`TabIcon.tsx`, 책갈피 · 종 · 검색은 `Icon.tsx`).

- **+** → `/add` — 촬영(M-06)으로. 넣을 인벤토리는 찍은 뒤 정보 입력(M-08) 맨 위 "넣을 곳"에서 고른다. 처음 골라 둘 곳은 **빈 칸 있는 것 중** 마지막에 연 내 인벤토리(쿠키 `inmyin-last-inventory`, 인벤토리 상세가 적는다) → 가장 최근에 아이템을 넣은 곳 → 가장 최근에 만든 곳(`lib/inventory/target.ts`). 모두 꽉 찼으면 찍기 전에 그 인벤토리(M-04, "프리미엄으로 늘리기")로, 인벤토리가 없으면 새 인벤토리 촬영. 로그인 안 했으면 로그인으로. `?category=` (모아보기 칩) · `?to=edit` (컴퓨터에서 사진을 먼저 골랐다 → 사진편집 M-07) 를 받는다
- 켜지는 범위: 발견은 `/discover`, 북마크는 `/bookmark…`, 프로필은 `/my…`, 나머지(`/inmyin`, `/u/…`, `/items/…`, `/notifications`)는 홈
- 웹 상단 메뉴(`WebNav`)도 같은 이름 · 순서 (홈 · 발견 · 북마크 · 프로필). + 는 메뉴 대신 오른쪽 끝 **"+ 추가"** 알약(웹 레이아웃 절)
- 화면 글자는 한글로 (2026-10-20 "한글로 통일"): 화면 제목 · 줄 제목 · 프로필 틀 탭은 **프로필 · 인벤토리 · 아이템**, 숫자 앞 말은 **전체**(`전체 9/125`), 인벤토리 + 메뉴는 **아이템 넣기**. 로고와 **INMYIN** 만 영어. 정렬 문구는 **"~순"을 붙여 쓴다** — 추천순 · 인기순 · 최신순 · 오래된순 (H-03 인기순 | 최신순, H-05 추천순 | 인기순, V-01 최신순 | 오래된순)

## 위에 붙는 줄

2026-10-20 당니님 결정(무늬 설계서 3절 A안). 폰은 스크롤해도 맨 위 한 줄이 남는다 — 홈 · INMYIN 은 갈래 줄(42), 발견은 제목 줄, 북마크는 갈래 줄, 프로필 · 상세 · 목록 화면은 헤더미니(64). 검색 · 칩은 흘러간다. 부품은 `StickyTop`: 흰 바탕 · 안전 영역만큼 위 여백 · 붙었을 때만 아래 1px 회색 선. 웹은 상단 바(`WebNav`, 76)만 붙고 갈래 줄은 흘러간다. 어두운 입력 화면 · 촬영 · 에디터 · 짐싸기처럼 화면 높이에 꽉 맞춘 화면은 해당 없음. 칸으로 스크롤할 때(`?added=`)는 `scroll-mt` 로 헤더 밑에 숨지 않게 한다

## A-01 · 로그인

로그인하지 않은 사람이 앱에 들어오면 가장 먼저 보는 화면. 주소는 `/login`.

- 로고
- Google로 로그인 / Kakao로 로그인 — 처음이면 A-03, 아니면 홈으로
- 글자 링크 두 개: 이메일 가입 → A-02, 이메일 로그인 → A-01a
- 맨 아래: 이용약관 · 개인정보 취급방침 · 문의 메일
- 이미 로그인한 사람이 오면 홈으로 돌려보낸다

## A-01a · 이메일 로그인

주소는 `/login/email`. 피그마 프레임은 없고 A-02와 같은 모양으로 만든다.

- 이메일 + 비밀번호 (눈 아이콘으로 보기/숨기기) → 로그인
- 비밀번호 칸 아래에 글자 링크 **비밀번호를 잊으셨나요?** → A-04
- 아래에 이메일 가입(A-02), 다른 방법으로 로그인(A-01)

## A-02 · 가입

이메일 가입 전용. 구글·카카오는 가입 화면 없이 A-01에서 바로 A-03으로 간다. 주소는 `/signup`.

1. 이메일 입력 → **인증번호 전송** → 메일로 온 숫자를 입력 → **확인**. 남은 시간 3:00 표시, 다시 보내기는 60초 뒤부터
   - 맞으면 "인증번호가 확인되었습니다."가 뜨고 시간 표시가 사라지며 이메일·인증번호 칸이 잠긴다
2. 비밀번호 입력 (8자 이상, 눈 아이콘으로 보기/숨기기) — 인증번호를 확인한 뒤에 입력할 수 있다
3. 약관 동의 — "모두 동의합니다" + 개별 항목. 항목은 `lib/terms.ts`
4. **가입하기** → 비밀번호 + 약관 동의 저장 → A-03

인증번호를 보내기 전에는 인증번호 칸과 약관이 보이지 않는다 (가입1 → 가입2 프레임).

이미 가입한 이메일(비밀번호가 있거나 구글·카카오로 연결된 계정)이면 메일을 보내지 않고 "이미 가입한 이메일입니다. 로그인해 주세요."라고 알려준다. 인증번호만 받고 그만둔 사람은 다시 와서 이어갈 수 있다.

## A-03 · 프로필 만들기

첫 로그인 직후 한 번만 나온다. 주소는 `/onboarding`. 이걸 끝내야 `User` 행이 생긴다.

- 닉네임 — 구글·카카오 이름이 있으면 미리 채워둔다
- 아이디(`handle`) — 프로필 주소 `/u/아이디`가 된다. 영소문자·숫자·`_`, 3~30자, 중복 불가
- 구글·카카오로 들어와 아직 약관에 동의한 적 없는 사람에게는 여기서 약관 동의를 받는다
- **등록하기** → 홈

프로필이 없는 사람이 다른 화면으로 가려 하면 여기로 돌려보낸다.

## A-04 · 비밀번호 재설정

이메일로 가입한 사람이 비밀번호를 잊었을 때. 주소는 `/reset-password`. A-02와 같은 모양에서 약관만 뺀다.

안내문: "가입한 이메일을 입력하면 본인인증 후 비밀번호를 재설정할 수 있습니다."

1. 이메일 입력 → **인증번호 전송** → 메일로 온 숫자를 입력 → **확인**. 남은 시간·다시 보내기·확인 뒤 잠금은 A-02와 같다
2. **새 비밀번호** 입력 (8자 이상, 눈 아이콘으로 보기/숨기기) — 인증번호를 확인한 뒤에 입력할 수 있다
3. **비밀번호 변경하기** → 새 비밀번호 저장 → 로그인된 상태로 홈

- 가입하지 않은 이메일이면 메일을 보내지 않고 "가입하지 않은 이메일입니다."라고 바로 알려준다. 계정을 새로 만들지 않는다
- 가입한 이메일이 기억나지 않는 사람을 위해 맨 아래에 안내를 둔다: 구글·카카오로 가입했다면 로그인 화면의 해당 버튼으로, 그래도 못 찾으면 문의 메일로
- 아이디(`handle`)로 이메일을 찾아주는 기능은 없다 — 아이디는 공개 정보라 남의 이메일 힌트가 새기 때문

## H-01 · 홈 › 아이템

주소는 `/`. 모든 사람의 공개 아이템을 최신순으로 뿌린다 — **내 것도 남들 사이에 같이 보인다** (내가 올린 것이 남에게 어떻게 보이는지 확인하는 데 좋다).

위에서부터: 홈 안의 갈래(**아이템** · INMYIN — 발견은 2026-10-20 하단 탭으로 나갔다, 같은 줄 오른쪽 끝에 **알림 종** → N-01, 안 본 알림이 있으면 빨간 점) → 그리드/리스트 토글 + 검색칸(토글이 왼쪽) → 카테고리 칩 한 줄 → 격자 또는 리스트 → "더 보기". 모아보기(M-13)와 같은 부품이라 생김새가 같다.

- **검색과 카테고리는 주소(`?q=&category=`)에 실어 서버가 거른다.** 모아보기는 내 것을 한 번에 다 읽어 브라우저에서 거르지만, 피드는 남의 것이 계속 늘어난다. 검색은 글자를 치고 0.35초 멈추면 물어본다. 뒤로 가기 · 새로고침 · 공유에 그대로 남는다
- **카테고리 칩은 전체 + 고정 8개**(가방 · 데스크 · 파우치 · 옷장 · 굿즈·수집 · 취미 · 집·주방 · 여행·아웃도어, 2026-10-19 당니님 결정 · 규칙 4). 아이템이 든 인벤토리의 카테고리로 거른다 — 아이템의 자유 태그는 여기서 안 쓴다. 카테고리를 안 고른 인벤토리의 아이템은 전체에서만 보인다. 주소로 온 값이 8개 밖이면(전에 쓰던 인기 태그 주소) 전체로 본다
- 한 번에 60개. 아래 "더 보기"를 누르면 마지막 것보다 오래된 것을 60개 더 읽어 붙인다
- 리스트 보기에서는 이름 아래에 **닉네임 · 인벤토리 이름** — 여러 사람의 것이 섞이는 화면이라
- **격자 칸의 주인은 웹에서만, 마우스를 올리면** 칸 왼쪽 위에 흰 알약(프로필 사진 20 + 닉네임)이 뜬다. 키보드로 칸에 와도(포커스) 뜬다. 폰은 칸 아래에 이름을 달면 지저분해서 안 보이고(2026-10-19 당니님), 누르면 상세(H-02)의 작성자 줄에서 본다. 칸의 읽어 주는 이름은 "아이템 이름 · 닉네임"
- 비공개 아이템 · 비공개 인벤토리 안의 것은 DB 규칙(RLS)이 알아서 뺀다
- 카드 탭 → H-02 (내 것이면 M-14)

## H-02 · 홈 › 아이템 상세

주소는 M-14 와 같은 `/items/[id]`. **어디서 왔는지로 모양이 정해진다** — 홈 피드에서 왔거나(`?from=home`) 남의 아이템이면 이 모양, 내 인벤토리에서 온 내 아이템이면 M-14. **홈에서 연 내 아이템도 남의 것과 똑같이 보인다** — 내가 올린 것이 남에게 어떻게 보이는지 그대로 보려고.

위에서부터 (피그마 H-02):

- 헤더: 닫기 × (**왔던 곳으로** — 홈에서 왔으면 홈) · 제목 "아이템". ⋮ 메뉴가 없다
- **작성자 줄** — 큰 프로필 사진(72px) · 닉네임 · 등록한 날(`26.09.05`) · 오른쪽에 검정 **팔로우** 버튼 (내 아이템이면 없다). 타유저 프로필(H-06)을 만들면 닉네임을 누르면 거기로 가고, 팔로우는 그 항목에서 동작을 붙인다
- 큰 사진 — 흰 바탕에 옅은 테두리 (M-14 의 회색 바탕과 다르다)
- 제목 줄 — 왼쪽 이름, 오른쪽 **하트 · 하트 수 · 댓글 · 댓글 수 · 북마크**. 하트와 북마크는 누르면 바로 켜지고 서버에 저장된다, 다시 누르면 꺼진다. 내 아이템에도 누를 수 있다. 말풍선을 누르면 아래 댓글 칸으로 내려가고 입력칸에 커서가 간다
  - **북마크**(책갈피) — 켜지면 검게 채운 책갈피. 북마크 탭(V-01)에 모인다. 플랜 한도(베이직 500개)가 차면 켜지지 않고 "북마크는 500개까지 모을 수 있어요". 몇 명이 북마크했는지는 보여주지 않는다
  - **하트** — 켜지면 검정으로 채운 하트(북마크처럼 "켜지면 채움" — 분홍은 알림 점 · 오류에만 쓴다), 옆에 하트 수. 한 사람이 한 번. 한도 없음, 모아 보는 곳 없음
- 설명 · 획득날짜 · 유통기한
- **댓글** — 화면 맨 아래. "댓글 n" 제목 아래 오래된 것부터 한 줄씩(프로필 사진 · 닉네임 · 시각 · 내용, 답글 없음), 화면 바닥에 붙어 있는 입력칸("댓글 달기…" + 게시). 500자까지. 쓰면 서버의 답을 기다리지 않고 바로 붙고, 실패하면 빠지며 글자가 돌아온다. **지우기는 줄을 왼쪽으로 밀어서** — 내 댓글과, 내 아이템에 달린 댓글(주인). 차단 사이의 댓글은 서로 안 보인다 (DB 규칙). M-14 에도 같은 댓글이 있다
- 아래의 칸들 — **홈에서 왔으면 없다.** 제목 · 내용에서 끝나고, 홈으로 돌아가면 이어서 본다 (처음엔 피드에서 근처에 있던 것들을 이었는데 "이것보다 먼저 올라온 것"만 쌓여 이상했다). 프로필 · 인벤토리(H-08)에서 왔으면 그 사람의 같은 인벤토리에서 공개 아이템만 당겨 붙인 것

## H-03 · 홈 › INMYIN 목록

주소는 `/inmyin`. 홈 갈래의 INMYIN. 모든 사람의 게시물을 카드로 — 4:5 이미지 · 아바타 닉네임 · 제목 한 줄. 폰은 2열, 웹은 5열. 카드 탭 → H-04.

- **카테고리 칩** — 전체 + 고정 8개 (H-01 과 같은 목록). 게시물에는 카테고리가 없어서 **게시물에 든 아이템의 인벤토리 카테고리**로 거른다 — 그 카테고리 인벤토리의 아이템이 하나라도 들었으면 보인다. 주소 `?category=`. 피그마 웹은 동그란 사진 칩이지만 카테고리마다 대표 사진이 없어 H-01 과 같은 칩으로
- **인기순 | 최신순** (오른쪽 끝, `?sort=popular`). 인기순은 최근 24시간에 받은 북마크 순 (DB 함수 `popular_posts`, `lib/ranking.ts`)
- 지워진 게시물 · 차단 사이의 게시물은 DB 규칙이 뺀다. 한 번에 60개 ("더 보기"는 게시물이 많아지면)

## H-04 · 홈 › INMYIN 상세

주소는 `/inmyin/[id]`. 목록(H-03) · 프로필의 카드에서 온다. 하단 탭이 없다. 아이템 상세(H-02)와 같은 틀:

- 헤더(× → 왔던 곳) · **작성자 줄**(72px 사진 · 닉네임 · 올린 날 · 팔로우) · **이미지**(흰 카드, 4:5) · 제목 줄 **[하트 · 하트 수 · 댓글 · 댓글 수 · 북마크]** · 내용 · **댓글**(아이템과 같은 부품, 입력칸은 화면 바닥)
- **이미지 위의 아이템 라벨**(이름 · 설명 한 줄, 반투명 검정)이 탭 영역. **인스타그램 태그처럼** — 평소엔 편집된 이미지만 보이고, 이미지를 한 번 누르면 라벨이 뜬다. 라벨을 누르면 그 아이템 상세(H-02 모양), 라벨 바깥(이미지)을 누르면 라벨이 다시 숨는다. 자리는 `PostItem` 의 비율 좌표. 지워졌거나 안 보이는 아이템(DB 규칙)은 라벨이 없다 — 이미지는 그대로, 누를 곳만 없다
- 내 게시물이면 헤더 오른쪽 **⋮ → 삭제하기** — 아이템과 달리 "지운 자리"가 없어서 되돌리기 칸 대신 한 번 더 묻는 판(차단과 같다). 지우면(`deletedAt`) 내 프로필로. 이미지 파일은 남는다
- 하트 · 북마크 · 댓글 · 알림은 아이템과 같은 표를 `targetType = post` 로 쓴다. 알림 글은 "회원님의 INMYIN 에 …"

## H-05 · 발견

주소는 `/discover`. 하단 탭의 발견 (2026-10-20 홈 갈래에서 나왔다 — 홈 갈래는 아이템 · INMYIN 둘). 맨 위는 갈래 줄 대신 같은 모양의 제목 줄 "발견"(종 없음). 사람을 찾는 탭. 오른쪽 끝에 **추천순 | 인기순** (기본은 추천순 — 아직 덜 알려진 사람을 띄운다). `?mode=popular`

| 필터 | 대상 | 정렬 |
| --- | --- | --- |
| 추천 | 누적 북마크 100 미만인 유저 (`RECOMMEND_THRESHOLD`, `lib/ranking.ts`) | 최근 1시간 북마크 수 |
| 인기 | 전체 유저 | 최근 24시간 북마크 수 |

- 줄 하나 = 아바타(56) · 닉네임 · 최근에 올린 날 · **팔로우** 버튼, 아래에 최근 INMYIN 세 개(4:5). 아바타 · 닉네임 → 프로필, 게시물 → 상세. 폰은 한 줄씩, 웹은 두 줄로
- 게시물이 있는 사람만. 나 자신과 차단 사이는 뺀다. **점수가 같으면 최근에 올린 사람 먼저** — 북마크가 아직 적을 때도 목록이 비지 않게
- 세는 것은 DB 함수 `discover_users`(security definer — 북마크 행은 본인만 볼 수 있어서). 돌려주는 것은 숫자뿐이라 누가 눌렀는지는 새지 않는다. 문턱 100 은 코드에서 넘긴다 (규칙 8)
- INMYIN 목록(H-03)의 인기순도 같은 방식(`popular_posts` — 최근 24시간 북마크 순, 같으면 최신순)

## H-06 ~ H-08 · 타유저 프로필

주소는 `/u/[아이디]`. 아이템 상세(H-02)의 작성자 줄, 팔로워 · 팔로잉 목록(M-12)의 줄에서 온다. 내 아이디를 열면 내 프로필(M-01)로 보낸다.

- **H-06 프로필** — 내 프로필(M-01)과 같은 틀(프로필 줄 → 세 탭 → 띠 → 이름 줄 → 격자). 위쪽 버튼이 **팔로우 · 프로필 공유**, 헤더는 ‹ 프로필 ⋮(차단). 띠 · 격자에는 **공개된 것만**, 처음 고른 인벤토리는 공개된 것 중 **순서 1번**(주인이 맨 앞에 둔 것이 대표). 띠에 + 칸 · 자물쇠 없음, 이름 줄 숫자는 `보이는 것/칸 수`, 오른쪽 버튼 없음. 비었으면 빈 가방 "공개된 아이템이 아직 없어요." · 인벤토리가 없으면 "공개된 인벤토리가 아직 없어요." (버튼 없음)
- 아이템 · INMYIN 탭 `/u/[아이디]/items` · `/u/[아이디]/inmyin` — 같은 프로필 줄 · 탭 아래에 모아보기(M-13) · 카드 격자. 숫자는 **보이는 것만**
- **H-08** `/u/[아이디]/inventories/[id]` — H-06 과 같은 화면, 그 인벤토리가 고른 상태. 띠를 누르면 주소가 바뀐다. 칸을 누르면 아이템은 상세(H-02), 담긴 인벤토리는 이 화면. **볼 수 없는 인벤토리**(비공개 · 지워짐 · 없음)를 주소로 열면 그 사람 프로필로 보내고 토스트 "지금은 볼 수 없는 인벤토리예요." 한 번 (`?notice=hidden`, 비공개인지 지워졌는지는 구분하지 않는다)
- 옛 H-07 `/u/[아이디]/inventories` 는 프로필로 보낸다
- 하단 탭: 세 탭 · H-08 모두 하단 탭이 있다 (홈 탭이 켜진 채). M-12 는 없다
- 차단한 사람의 프로필: 프로필 줄은 그대로, 탭 아래는 가방 없이 글 한 줄 "차단한 사용자예요. 차단을 풀면 다시 볼 수 있어요."

**비공개 아이템 · 비공개 인벤토리는 아예 보이지 않는다.** 저장은 칸 번호 그대로 두고, 읽을 때만 보이는 것을 모아 다시 줄을 세운다. 무엇이 보이는지는 화면이 아니라 DB 규칙(RLS)이 정한다 — `lib/profile/public-queries.ts` 는 돌아온 것을 줄 세우기만 한다.

### 차단

- H-06 헤더 오른쪽 **⋮ → 차단하기**. 아래에서 올라오는 판으로 한 번 더 묻는다 (팔로우가 끊기므로). 차단하면 서로의 아이템 · 인벤토리가 **양쪽 다** 안 보이고(홈 · 검색 · 프로필 · 북마크 탭 어디서든), 서로의 팔로우는 끊긴다
- 차단한 사람의 프로필은 열리지만 숫자와 목록이 비어 보이고, 팔로우 버튼 자리에 "차단함". ⋮ → 차단 해제
- **설정 › 일반 › 차단한 사용자** (`/my/settings/blocked`) — 목록과 해제 버튼. 해제해도 끊긴 팔로우는 돌아오지 않는다
- 누가 나를 차단했는지는 알 수 없다 — 그 사람의 것이 그냥 안 보일 뿐이다. 이것도 DB 규칙(`blocked_between`)이 정한다

## M-01 · 프로필 › 내 프로필

프로필 탭의 첫 화면 = **프로필 줄 + 인벤토리 띠 + 격자** (0단계 결정 · 무늬 빈화면프로필설계 v01). 폰도 웹도 같은 순서이고, 웹은 프로필 줄이 넓어지고 격자가 회색 판에 들어간다.

주소는 `/my`. 하단 탭이 있다. 위에서부터:

- 헤더: 톱니(→ 설정 M-02) · 제목 "프로필" (웹은 프로필 줄 오른쪽 위 톱니)
- 동그란 프로필 사진(없으면 회색 원에 사람 그림 — 무늬 1안 "떠 있는 사람": 선 1.75 머리 원 + 반원 몸, 선 색 #c1c1c1, 24px 미만 아바타는 채움. 2026-10-21 당니님 결정, `components/profile/Avatar.tsx` PersonMark) · 아이디 · 닉네임(프리미엄이면 검정 원 안의 흰 별) · `팔로워 0 팔로잉 0`
- **프로필 관리**(검정) / **프로필 공유**(흰 바탕 + 회색 테두리) 버튼 두 개 — 한 줄에 검정은 하나
- **세 탭** 인벤토리 · 아이템 · INMYIN — 폰에도 있다(16px · 사이 36 · 밑줄 화면 끝까지, 웹 20px · 사이 56). 인벤토리 `/my`, 아이템 `/my/items`(M-13), INMYIN `/my/inmyin`(카드 격자 + 빈 가방 "INMYIN 만들기")
- **인벤토리 띠** — 순서(인벤토리 관리에서 바꾼다)대로 썸네일 52(테두리 포함 60) + 아래 이름 11px. 고른 것 검정 테두리 · 굵은 이름. 비공개면 썸네일 오른쪽 아래 흰 원 안 자물쇠. 맨 끝 **+ 칸 "만들기"**(사진 업로드 / 찍기 메뉴, 컴퓨터는 파일창 바로 — M-03 + 와 같다, 한도에 닿으면 없음). 여기서 들어간 촬영 · 사진편집 · 인벤토리 만들기의 × 는 **프로필로 돌아온다**(`?back=`, 2026-10-21 당니님 — 관리의 + 줄에서 들어가면 관리로). 인벤토리 없음 빈 화면의 "인벤토리 만들기"도 같다. 저장하면 늘 새 인벤토리의 격자로. 누르면 `/my/inventories/[id]` 로 주소가 바뀐다(M-04). 고른 칸이 띠 밖이면 보이는 곳까지 스크롤(고른 것이 바뀔 때만)
- **이름 줄** — `데스크 10/25`(쓴 칸/칸 수, 태그로 걸러도 전체) · 비공개면 자물쇠 · 오른쪽 **관리**(→ M-03) · **짐싸기**(→ M-05) 작은 테두리 버튼
- **카테고리 안내** (내 것, 고정 카테고리를 아직 안 골랐을 때만) — 이름 줄 바로 아래 회색 작은 글씨 한 줄 "홈 · 발견에 보일 카테고리를 골라 주세요. **고르기**"(검정 굵게 밑줄 → 그 인벤토리 수정 화면). 수정 화면에서 저장하거나 × 를 누르면 **이 프로필 격자의 그 인벤토리로 돌아온다**(`?back=`, 2026-10-21 당니님 — 관리 화면에서 들어온 수정은 관리로). 고르면 사라진다. 카테고리 칸이 생기기 전(2026-10-21) 만든 인벤토리용
- 토글 · 칩 · 격자/리스트 — M-04 그대로
- **처음 고른 인벤토리 = 마지막에 연 것**(쿠키 `inmyin-last-inventory`, 하단 탭 + 와 같은 값) → 없거나 지워졌으면 순서 1번 (2026-10-20 당니님 결정)
- 비었으면 격자 대신 **빈 가방**(아래 "빈 화면"): "데스크가 비어 있어요. 물건을 찍어 넣어 보세요." + **아이템 넣기** + 글자 링크 **인벤토리 가져오기**. 칩을 골라 0개면 가방 없이 "이 태그에는 아직 없어요."
- 인벤토리가 하나도 없으면 띠 · 이름 줄 · 토글 · 칩 없이 탭 바로 아래 빈 가방 "아직 인벤토리가 없어요. 옷장, 가방, 서랍… 물건이 있는 곳부터 하나 만들어 보세요." + **인벤토리 만들기**(띠 + 칸과 같은 메뉴)

### 빈 화면 (빈 가방)

`components/ui/EmptyBag.tsx` — 랜딩 가방 그림(`public/landing/bag.webp`) 120 × 131 · 한 문장(회색) · 검정 알약 버튼 하나 · 보조 글자 링크. 화면이 뜨고 0.3초 뒤 한 번 들썩(랜딩과 같은 몸짓, 움직임 줄이기면 없음). 북마크 · 홈 · 모아보기 · INMYIN 목록 · 프로필 격자가 비었을 때 쓴다. **걸러서 0개 · 차단 · 바텀시트 안 · 발견은 가방 없이 글 한 줄** — 비어 있는 게 아니라서.

**아직 없는 기능의 버튼은 빼지 않고 자리만 잡아 둔다.** 누르면 아래에 "○○는 곧 만들어요."가 잠깐 뜬다 — 버튼을 빼면 화면이 디자인과 달라지고, 눌러도 아무 일이 없으면 고장난 줄 안다. 지금 그런 것: INMYIN 갈래(3단계). 팔로워 · 팔로잉 숫자는 진짜 값이고, 누르면 목록(M-12)으로 간다.

**프로필 공유** — 폰에서는 공유 시트(카톡 · 메시지 · 에어드롭…)가 뜨고, 공유 시트가 없는 컴퓨터에서는 링크가 복사된다 ("프로필 링크를 복사했어요."). 링크는 `/u/아이디`. 받은 사람은 로그인 없이 볼 수 있다 — 팔로우 · 하트 · 북마크 · 댓글을 누르면 로그인 화면으로 가고, 로그인하면 보던 화면으로 돌아온다. 타유저 프로필(H-06)의 공유 버튼도 같다.

### 프로필 관리

주소는 `/my/edit`. 하단 탭이 없는 어두운 입력 화면 — 피그마에 그림이 없어서 다른 정보 입력 화면(M-08)과 같은 모양으로 만들었다. 헤더는 닫기(×) · "프로필 관리", 아래 버튼은 "수정하기". 저장하면 내 프로필로 돌아간다.

## M-03 · 인벤토리 관리

**인벤토리 관리** — 이름 · 순서 · 삭제. 주소는 `/my/inventories`. 프로필 격자 이름 줄의 **관리**에서 온다. 설정과 같은 깊이라 **하단 탭 없이** 뒤로(→ `/my`) 헤더 "인벤토리 관리". 웹은 설정처럼 폰 모양을 가운데 448 로. 띠 · 격자는 프로필이 한다.

있는 인벤토리와 그 다음의 + 줄 하나만 그린다. **빈 자리는 그리지 않는다** — 어차피 + 가 항상 있다.

- 우측 위 `전체 9/125` 아래에 "순서대로 띠에 놓여요. 맨 앞이 남에게 먼저 보여요."
- 줄 하나 = 썸네일 칸 + 이름(비공개면 자물쇠) + `n/25` (든 아이템 수 / 칸 수) + 오른쪽 끝 **순서 손잡이**(세 줄). 사진은 필수라 썸네일이 항상 있다
- **+ 줄은 마지막 인벤토리 다음에 하나만.** 옆에 "+를 눌러 인벤토리를 추가하세요."
- 줄을 누르면 **수정 화면**(이름 · 카테고리 · 태그 · 공개)으로 간다. 줄을 밀면 수정 · 삭제 — 방향도 생김새도 M-04 의 리스트와 같다 (오른쪽으로 밀면 회색 연필, 왼쪽으로 밀면 검정 휴지통). 마우스로 끌어도 된다
- **순서** — 손잡이를 누른 채 위아래로 끌면 줄이 들리고 다른 줄이 비켜난다. 놓으면 화면부터 바뀌고 서버가 `sort_order` 를 0부터 다시 적는다(`reorderInventories`, 실패하면 되돌리고 알림). 손잡이에서만 끌 수 있어 줄의 가로 밀기와 안 섞인다. 키보드는 손잡이에서 ↑↓
- **인벤토리는 비어 있을 때만 삭제할 수 있다.** 아이템이나 다른 인벤토리가 들어 있으면 막고, "○○에 든 것이 있어요. 먼저 비운 뒤에 삭제할 수 있어요."라고 안내한다. 화면에서도 막고 서버에서도 한 번 더 막는다
- 삭제는 아이템과 같은 방식이다: 확인 창 없이 바로 지우고, 그 줄이 5초 동안 "되돌리기" 줄로 남는다. 되돌리면 원래 자리로 돌아온다 (목록의 순서는 지워도 그대로다)
- **수정은 만들 때와 같은 화면**에 지금 값을 채워서 연다. 주소는 `/my/inventories/[id]/edit`, 제목과 버튼은 "수정하기". 저장 · × 뒤에는 관리로 돌아온다(프로필 안내 줄 "고르기"로 왔으면 그 인벤토리 격자로 — 주소의 `?back=`, 사진 바꾸기를 거쳐도 실려 다닌다. 이 사이트 안 경로만 받는다 `lib/nav/return-to.ts`). 이름 · 카테고리 · 태그 · 공개와 **대표 사진**을 고친다. 사진을 누르거나 그 아래 "사진 바꾸기"(흰 바탕 회색 테두리 32)를 누르면 촬영(M-06, 폰) · 사진 고르기 창(컴퓨터) → 사진편집(M-07)을 다시 거쳐 수정 화면으로 돌아온다(`/my/inventories/[id]/edit/camera` · `/photo`). 아이템 수정과 같은 규칙 — 아래 M-04 "밀어서 수정 · 삭제"
- **수정에서 없앤 태그는 그 태그를 달고 있던 아이템에서도 뗀다.** 안 그러면 어디에도 안 보이는 태그가 아이템에 남는다. 그 아이템들은 "전체"에서만 보이게 된다 (CLAUDE.md 규칙 4)
- 우측 위 `전체 9/125`(알약 없이 회색 작은 글자 — 상태) = 내 아이템 전체 수 / (인벤토리 한도 × 칸 수)
- 베이직: 5개까지, 판당 25칸 · 프리미엄: 20개까지, 판당 50칸
- 한도에 닿으면 + 칸이 사라지고 아래에 **인벤토리 늘리기** 버튼이 나온다 → 플랜 결제 화면 (4단계 전까지는 "준비 중" 안내)

### + 를 누르면

1. 작은 메뉴: **사진 업로드 / 사진 찍기**. 데스크톱에서는 메뉴 없이 바로 파일 고르기
2. 사진 편집 (M-07) — 주소는 `/my/inventories/new/edit`, 아이템 편집과 같은 화면이다
3. 인벤토리 정보 입력 → 저장하면 **새 인벤토리의 프로필 격자**(`/my/inventories/[새 id]`)로 — 빈 가방의 "아이템 넣기"로 이어진다

사진 찍기는 촬영 화면(M-06)을 연다 — 주소는 `/my/inventories/new/camera`, 아이템 촬영과 같은 화면이다. 이 메뉴는 관리의 + 줄 · 프로필 띠의 + 칸 · 인벤토리 없음 빈 화면에 있다(`useAddInventory`) — 아이템은 빈 칸에서 이미 한 번 고르므로(M-04) 바로 촬영 화면으로 가고 거기서 갤러리를 고른다.

### 인벤토리 정보 입력

| 필드 | 필수 | 형태 |
| --- | --- | --- |
| 인벤토리 이름 | ● | 한 줄 텍스트 + 드롭다운. 드롭다운에는 추천 8종(가방 · 데스크 · 파우치 · 옷장 · 굿즈 · 냉장고 · 집 · 생활용품) |

| 공개 | | 토글. 기본은 켜짐. **끄면 안에 든 아이템(공개여도) · 담긴 인벤토리까지 남에게 통째로 안 보인다.** 내 화면에서는 그대로 보인다 |

## M-04 · 프로필 › 인벤토리 상세

주소는 `/my/inventories/[id]`. **내 프로필(M-01)과 같은 화면**에서 그 인벤토리가 고른 상태 — 프로필 줄 · 세 탭 · 하단 탭이 있다. `?view= · ?category= · ?added= · ?deleted=` 그대로. 열면 "마지막에 연 인벤토리"로 쿠키에 적는다.

위에서부터: 프로필 줄 · 세 탭 → 인벤토리 띠(M-01) → 이름 줄 `데스크 16/25` · 관리 · 짐싸기 → 그리드/리스트 토글 + 태그 칩(맨 앞은 전체) → 격자 또는 리스트. 사용량 숫자는 화면 바닥이 아니라 이름 줄에 있다.

채워진 칸을 누르면 아이템은 상세(M-14)로, 안에 담긴 인벤토리는 그 인벤토리로 간다.

\+ 칸을 누르면 메뉴가 뜨고, 두 가지로 채운다.

1. **아이템 넣기** — 새로 사진 찍어 등록하기 → M-06. 데스크톱에서는 "휴대폰에서 등록해 주세요" 안내
2. **인벤토리 가져오기** — 다른 인벤토리를 통째로 이 칸에 담는다. 이미 다른 곳에 들어가 있는 인벤토리는 고를 수 없게 막는다

### 인벤토리 가져오기 · 꺼내기

- "인벤토리 가져오기"를 누르면 **아래에서 목록이 올라온다.** 내 다른 인벤토리가 목록(M-03)과 같은 모양의 줄(사진 · 이름 · `n/25`)로 나오고, 하나를 누르면 **안에 든 것과 함께 통째로** 맨 뒤 칸에 담긴다 (누르는 즉시 "톡" 하고 나타난다)
- **담을 수 없는 것은 목록에서 빼지 않고 흐리게 보여주고, 이름 아래에 이유를 적는다** — 그냥 빼 버리면 어디 갔는지 찾게 된다
  - "이미 여기에 들어 있어요" · "○○ 안에 들어 있어요" (부모는 항상 하나 — CLAUDE.md 규칙 2)
  - "이 인벤토리를 담고 있어요" (자기 안에 든 것 속으로는 들어갈 수 없다)
  - "5겹까지만 겹쳐 담을 수 있어요"
  - 화면은 미리 걸러 보여줄 뿐이고, 최종 판단은 DB가 한다. 막히면 칸을 도로 빼고 이유를 띄운다
- 담긴 인벤토리의 칸을 **누르면 그 인벤토리로 들어간다.** **길게 누르면 "꺼내기"** (그리드와 리스트 둘 다. 데스크톱은 마우스 오른쪽 버튼도) — 밖으로 꺼내도 안에 든 것은 그대로고, 인벤토리 관리(M-03)에서 계속 보인다. 되돌리기는 없다: 다시 가져오면 된다 (맨 뒤 칸으로 들어온다)
- 담긴 인벤토리 자체의 수정 · 삭제는 인벤토리 관리(M-03)에서 한다. 담긴 채로 지웠다가 되돌리면 부모 안의 원래 순서로 돌아온다
- 담긴 인벤토리는 부모의 칸을 **한 칸** 쓴다. 그 안에 든 아이템 수는 부모의 `16/25` 에 들어가지 않는다
- 다른 인벤토리로 옮길 때는 짐싸기(M-05)를 쓴다

### 밀어서 수정 · 삭제

- **왼쪽으로 밀면** 오른쪽에서 검정 휴지통이 나온다 → 삭제 (`deletedAt` 기록)
- **오른쪽으로 밀면** 왼쪽에서 회색 연필이 나온다 → 수정
- 줄의 내용은 움직이지 않는다. 너비 77 의 색 블록이 가장자리에서 줄을 덮으며 나온다. 반 넘게 나왔을 때 손을 떼면 끝까지 열리고, 아니면 닫힌다. 블록을 눌러야 실행된다 — 밀기만 해서는 지워지지 않는다
- 한 번에 한 줄만 열린다. 열린 채 줄을 누르면 상세로 가지 않고 닫힌다
- 밀기는 **리스트의 줄**에서 한다. 인벤토리 관리(M-03)의 줄도 같은 동작으로 인벤토리를 수정 · 삭제한다
- **그리드의 칸은 밀지 않고 길게 누른다.** 칸이 작아서 밀기가 어색하다. 0.5초 누르면 아이템 상세(M-14)의 ⋮ 와 같은 메뉴(삭제하기 / 수정하기)가 뜬다. 데스크톱에서는 마우스 오른쪽 버튼도 같은 메뉴를 띄운다
- **삭제는 확인 창 없이 바로 지우고, 지운 바로 그 자리가 5초 동안 "되돌리기" 칸으로 남는다.** 사진은 흐려지고, 검정 되돌리기 화살표와 글자가 나오고, 검은 선이 5초 동안 남은 시간을 알려준다 — **그리드의 칸에서는 테두리를 따라 한 바퀴 돌며 지워지고** (위 가운데에서 시작해 시계 방향), **리스트의 줄에서는 아래의 선이 줄어든다.** 리스트의 줄에는 이름 아래에 "삭제했어요"가 붙는다. 5초가 지나면 그 칸이 사라지고 뒤의 칸들이 당겨 붙는다
  - **화면 아래에 뜨는 안내(토스트)로 하지 않는다.** 지운 자리와 멀고 어두워서 눈에 띄지 않았다. 되돌리기는 눈과 손가락이 이미 가 있는 곳에 있어야 한다
  - 되돌리면 맨 뒤가 아니라 **원래 있던 순서**로 돌아가고, 그 칸을 잠깐 강조한다
  - 되돌리기 칸은 눌러도 상세로 가지 않는다. 찬 칸으로 세지 않는다 (`16/25` 는 지운 즉시 줄어든다)
  - 5초 안에 다른 아이템을 또 지우면 앞의 것은 그대로 확정된다. 처음 5초 → 빠르게 느껴져 7초로 늘렸다가 → 실제로 써 보니 길어서 5초로 되돌렸다
  - **삭제도 되돌리기도 누른 즉시 화면부터 바뀐다.** 서버의 답을 기다리지 않는다 — 답이 늦으면 멈춘 것처럼 보이고, 기다리다 여러 번 누르게 된다. 서버에 알리는 일은 뒤에서 하고, 실패했을 때만 칸을 원래대로 돌려놓고 안내를 띄운다. 같은 요청이 두 번 와도(이미 지워짐 · 이미 살아 있음) 서버는 성공으로 답한다
  - **되돌리기 칸이 떠 있는 동안 다른 화면으로 넘어가도 된다.** 삭제는 누른 순간 이미 끝났고, 이 칸은 되살릴 기회일 뿐이다. 넘어가면 그대로 확정된다
- **수정은 정보 입력(M-08)과 같은 화면**에 지금 값을 채워서 연다. 헤더의 제목과 아래 버튼은 "저장하기"가 아니라 **"수정하기"**다. 주소는 `/items/[itemId]/edit`. 맨 위에 사진(140 정사각형, 칸과 같은 옅은 회색 바탕)과 "사진 바꾸기"(흰 바탕 회색 테두리 32). 사진이나 버튼을 누르면 촬영(M-06, 폰) · 사진 고르기 창(컴퓨터) → 사진편집(M-07, 배경제거 기본 켜짐 · 누끼 손질 · 보정)을 다시 거쳐 수정 화면으로 돌아온다(`/items/[itemId]/edit/camera` · `/photo`). 저장하면 아이템 상세(M-14)로 간다
  - 쓰던 이름 · 설명 등은 다녀와도 남는다(떠나기 전에 브라우저 메모리에 맡김 — 새로고침하면 저장된 값으로 다시 연다)
  - 사진편집에서 저장하기를 눌러야 새 사진이 되고, 사진 아래에 "수정하기를 누르면 새 사진으로 바뀌어요."가 뜬다. 촬영 × · 사진편집 ‹ 로 돌아오면 사진은 그대로. 수정하기를 누르지 않고 닫으면 원래 사진 그대로
  - 새 사진은 새 파일 이름으로 올린다(같은 주소에 덮어쓰면 옛 사진이 캐시에 남는다). 옛 사진 파일은 지우지 않는다 — 저장소에 지우는 권한이 없고(규칙 6), 지난 INMYIN 캔버스가 옛 주소를 쓰고 있을 수 있다
- 칸 안에 담긴 인벤토리에는 수정 · 삭제가 없다 (인벤토리 관리 M-03 에서 한다). 길게 누르면 "꺼내기"만 뜬다

**이미 등록된 아이템은 불러올 수 없다.** 실제 물건은 두 곳에 동시에 존재할 수 없기 때문이다. 옮기려면 짐싸기를 쓴다. 같은 이유로, 이미 다른 인벤토리 안에 들어가 있는 인벤토리도 또 불러올 수 없다. 한 줄로 이어지는 중첩은 5겹까지 (예: 집 › 방 › 가방 › 작은 가방 › 파우치).

### 새 아이템이 들어가는 자리

**항상 마지막 아이템의 다음 칸.** 첫 줄에 끼워 넣어 기존 아이템을 밀어내지 않는다. 새 것이 끼어들어 자리가 바뀌면 "어디에 뭘 뒀는지"라는 이 앱의 핵심 가치가 무너진다.

**중간에서 아이템을 지우면 뒤의 아이템들이 한 칸씩 당겨 붙는다.** 구멍은 남지 않는다. 짐싸기로 아이템이 빠져나간 자리도 마찬가지다.

추가 직후 처리:

- 새로 들어간 칸으로 자동 스크롤
- 그 칸이 움직여서 알려준다. **보라색 테두리를 번쩍이는 방식은 어색해서 버렸다**
  - 그리드의 칸: 작게(0.7배) 시작해 살짝 넘치게(1.06배) 커졌다가 제 크기로 돌아온다 — 홈 화면에 앱이 깔릴 때 같은 "톡". 0.5초
  - 리스트의 줄: 옅은 회색이 깔렸다가 서서히 빠진다 — 목록에서 "방금 바뀐 줄"을 알릴 때 흔히 쓰는 방식. 1.4초
  - 새 칸이 화면 밖에 있으면 스크롤로 데려와서 **도착한 순간** 움직인다. 이미 눈에 보이던 칸은 사라졌다 나타나면 깜빡이므로, 그때는 제자리에서 한 번 부푼다(1.1배)
  - 삭제를 되돌렸을 때도 같은 움직임이다

**리스트 보기도 격자와 같은 순서**이고, + 줄이 맨 아래에 온다. 최신순으로 보고 싶을 때는 아이템 모아보기(M-13)를 쓴다.

### 추가 버튼

- **+ 칸은 마지막 아이템의 다음 칸에 하나만.** 아이템이 없으면 첫 번째 칸이다. 나머지 빈 칸은 그리지 않는다
- **떠 있는 + 는 없다**(2026-10-20 당니님 결정). 하단 탭 + 가 "마지막에 연 인벤토리"(= 지금 보는 것)를 골라 두고, 웹은 상단 "+ 추가"가 있다
- + 칸 › **아이템 넣기**는 이 인벤토리가 골라진 채 바로 촬영(폰) · 사진 고르기(컴퓨터)로 간다. 넣을 곳은 정보 입력(M-08)에서 바꿀 수 있다
- 비었으면 + 칸 대신 빈 가방 + **아이템 넣기** · **인벤토리 가져오기** (M-01)
- **칸이 다 차면** + 칸 자리에 "칸이 가득 찼어요 · 프리미엄으로 늘리기"를 띄운다. + 를 그냥 없애면 기능이 사라진 줄 안다
- 사용량 `16/25` 는 이름 줄에 (화면 바닥 알약은 없앴다 — 하단 탭과 겹치고 격자가 짧으면 떠 있었다)

### 칸 수에 따른 격자

| 칸 수 | 열 |
| --- | --- |
| 25 (베이직) | 설정(M-02)에서 고른 3 또는 4. 기본 4 |
| 50 (프리미엄) | 4 |
| 100+ | 5 |

처음엔 25칸을 3열로 그렸는데 써 보니 칸이 커 보였고, 3과 4는 취향이 갈려서 설정에서 고르게 했다. 5열은 너무 작아서 뺐다.

**채워진 칸의 바탕은 옅은 회색(gray-1), + 칸의 바탕은 흰색이다.** 배경을 지운 사진은 옅은 회색 위에 물건만 놓인다. + 는 피그마 그림보다 굵기를 반으로 줄였다.

**빈 칸은 그리지 않는다.** 채워진 칸과 그 다음의 + 칸만 보인다. 인벤토리 띠에도 빈 칸을 두지 않는다. 남은 용량은 아래의 `16/25` 가 알려준다.

그리드/리스트 토글은 **회색 바탕에 지금 보기 = 검정 · 다른 쪽 = 회색 아이콘**이다 — 버튼이 아니라 상태라서. 태그 칩은 **글자만**(고름 = 검정 굵게, 기본 = 회색, 칩 사이 20) — 상자가 없어 토글과 섞이지 않는다. 헤더의 짐싸기는 흰 바탕 + 회색 테두리, 아래 `16/25` 는 흰 알약 위 회색 작은 글자. 헤더 제목은 인벤토리 이름이 아니라 **"인벤토리" 고정**이다 — 띠로 인벤토리를 오가는 화면이라 제목이 바뀌지 않는 편이 낫다.

## M-05 · 짐싸기

주소는 `/my/inventories/[id]/packing`. 인벤토리 상세(M-04) 우측 상단의 **짐싸기** 버튼 → 인벤토리 두 개가 위아래로 동시에 열린다. 버튼을 누른 인벤토리가 위쪽, 다른 하나가 아래쪽이다. 한쪽에서 아이템을 누르면 반대쪽으로 넘어가고 즉시 자동 저장된다. 하단 탭이 없다.

화면: 헤더(닫기 × · 제목 "짐싸기") 아래를 **높이 반씩** 나눠 쓴다. 각 절반은 인벤토리 띠와 그 아래의 칸들뿐이고, `1/25` 는 칸 위 아래쪽에 흰 알약으로 떠 있다. 칸이 많으면 그 절반 안에서만 스크롤한다.

**그리드/리스트 토글과 태그 칩은 짐싸기에 없다 (피그마에는 있다).** 절반은 좁아서, 그 한 줄을 빼야 칸이 두 줄 넘게 보인다. 짐싸기는 찾아보는 화면이 아니라 옮기는 화면이고, 같은 면적이면 그리드가 가장 많이 보여준다. 항상 그리드, 항상 전체다. 닫기(×)는 들어온 인벤토리의 상세로 돌아간다.

- 한 번에 하나씩만 옮긴다. 다중 선택 없음
- 되돌리기 버튼 없음 — 반대쪽에서 다시 누르면 돌아온다
- 받는 쪽이 꽉 찼으면 "○○가 꽉 찼습니다. 이동이 불가합니다" 알림을 띄우고 이동하지 않는다. 이름의 받침에 따라 "가방**이**" / "냉장고**가**"로 맞춘다
- **같은 인벤토리를 양쪽에 열 수 없다.** 반대쪽에 열려 있는 인벤토리는 띠에서 어둡게 보이고 고를 수 없다. 그 인벤토리가 이쪽 인벤토리 안에 담겨 있으면 그 칸도 어둡게 보인다
- **넘어온 아이템은 받는 쪽의 맨 뒤 칸에 들어간다** (CLAUDE.md 규칙 3). 빠져나간 자리는 뒤의 것들이 당겨 붙는다. 그래서 옮겼다가 돌려보내면 원래 자리가 아니라 맨 뒤로 간다. 넘어온 칸은 "톡" 하고 나타난다
- **누르는 즉시 화면부터 바뀌고** 저장은 뒤에서 한다. 실패하면 원래 자리로 돌려놓고 안내한다. 띠에서 인벤토리를 갈아탈 때도 기다리지 않게, 들어올 때 내 인벤토리 전부를 한 번에 읽어 둔다
- **아이템의 태그는 옮겨도 그대로다.** 받는 쪽 인벤토리에 그 태그가 없으면 거기서는 "전체"에서만 보이고, 돌려보내면 원래대로다 (태그는 인벤토리마다 다르다 — 규칙 4)
- 이 화면에서는 아이템을 눌러도 상세로 가지 않고, 길게 누르기 · 밀기(수정 · 삭제)도 없다
- **안에 담긴 인벤토리도 아이템처럼 눌러서 옮긴다.** 자기 안에 든 것 속으로 넣으려 하거나 5겹을 넘으면 DB가 막고, 칸을 원래 자리로 돌려놓은 뒤 이유를 띄운다
- 인벤토리가 하나뿐이면 아래쪽에 "짐을 옮기려면 인벤토리가 하나 더 필요해요."와 인벤토리 관리로 가는 링크를 보여준다

## M-06 · 아이템 촬영

주소는 `/my/inventories/[id]/items/camera`. 화면 가득 카메라가 나오고 하단 탭이 없다.

위에 닫기(×)와 제목 "촬영모드", 가운데에 둥근 네모 프레임, 아래 가운데에 셔터, 그 왼쪽에 "갤러리에서 선택" 버튼. 실제 썸네일로 쓰일 영역(프레임) 밖은 어둡게 마스크 처리된다. 칸이 정사각형이라 프레임도 정사각형이다.

- **찍으면 사진이 두 장 만들어진다.** 프레임 안쪽만 잘라낸 것이 칸에 보이는 썸네일이 되고, 프레임 밖까지 찍힌 전체는 원본으로 보관한다 (CLAUDE.md 규칙 7)
- 갤러리에서 고른 사진은 프레임이 없으므로 자르지 않는다. 썸네일과 원본이 같은 사진이다
- 찍거나 고르면 편집(M-07)으로 간다
- 카메라 권한을 거절했거나 카메라가 없으면 프레임 안에 "카메라를 쓸 수 없어요" 안내를 띄운다. 갤러리 버튼은 그대로 쓸 수 있다
- 다른 앱으로 나가면 카메라를 끄고, 돌아오면 다시 켠다
- **프레임이 어두우면 프레임 아래쪽에 "조금 더 밝은 곳에서 찍어 보세요"를 띄운다.** 1.5초마다 프레임 쪽 영상을 아주 작게(24×24) 줄여 밝기 평균만 본다. 평균이 55(0~255) 아래면 띄우고, 70 위로 올라가야 지운다 — 문턱 근처에서 깜빡이지 않게. 막지는 않는다, 찍을 수 있다
- 카메라는 `https` 주소(와 개발용 `localhost`)에서만 켜진다 — 브라우저의 규칙이다
- 인벤토리 만들기의 "사진 찍기"(M-03)도 같은 화면을 쓴다

**웹에서는 이 화면이 없다.** 데스크톱에서는 등록 버튼 자리에 "휴대폰에서 등록해 주세요" 알림을 띄운다.

## M-07 · 아이템 편집

주소는 `/my/inventories/[id]/items/edit`. 검은 화면이고 하단 탭이 없다.

위에 뒤로(‹)와 제목 "사진편집", 오른쪽 위에 **배경제거** 버튼(원 46 안의 별 — 꺼짐 회색 원 + 선 별, 켜짐 흰 원 + 채운 별), 가운데에 사진, 아래에 **저장하기**. 사진은 칸과 같은 회색 바탕 · 같은 자르기(가운데 정사각형)로 보여준다 — 격자에서 어떻게 보일지 그대로다.

- **들어오면 배경제거가 켜진 채로 시작하고 바로 배경을 지운다 (누끼 따기, 2026-10-20 기본값으로).** 배경이 남은 사진이 피드 격자와 INMYIN 에디터 결과물을 지저분하게 하던 가장 큰 원인이라서(2026-10-19 당니님). 배경제거를 누르면 원래 사진으로 돌아오고, 다시 누르면 물건만 남는다. 지운 결과는 기억해 두어서 껐다 켜도 다시 기다리지 않는다
- 배경을 지우는 일은 폰 안에서 한다 — 사진이 밖으로 나가지 않는다. **처음 한 번은 AI 모델을 내려받느라 오래 걸린다** (컴퓨터에서 20초쯤). 사진은 가리지 않고(그사이 켠 자동 보정 · 세부 조정이 그대로 보인다), 버튼은 막지 않는다
  - **지우는 동안의 연출 — 테두리 잇기** (무늬 누끼로딩설계 v01 B안, 2026-10-20 당니님). 사진 테두리 안쪽 6px 를 따라 1.5px 흰 선이 진행률만큼 이어진다(내려받기 80% + 계산 네 단계 20%, 줄지 않음. 진행률을 모르면 느린 가짜 곡선, 최대 90%). 밝은 머리 한 토막은 늘 돌아서 숫자가 멈춰도 살아 있다. 배경제거 별 버튼은 작은 별만 반짝인다
  - 다 지우면 남은 테두리가 0.28초에 닫히고, 테두리 모양 그대로 바깥에서 안으로 원래 사진이 걷혀(0.62초) 밑의 누끼가 드러난다 — 뚝 바뀌지 않는다. 보정이 켜져 있으면 걷히는 쪽도 보정본. 배경제거를 껐다 다시 켤 때도 매번 걷힘을 보여준다. 걷힌 뒤 "손질" 알약이 나타난다
  - 사진 아래쪽 알약(실패 알림과 같은 자리 · 모양): 1.5초 안에 끝나면 안 띄움 → "배경을 지우는 중" → 4초가 넘고 처음이면 "처음 한 번만 조금 오래 걸려요"(한 번 성공하면 localStorage `inmyin-bg-model-ready` 로 기억, 다음부터는 안 씀). 진행률을 알면 옆에 회색 `41%`
  - 움직임 줄이기를 켜면 밝은 머리 · 별 반짝임이 없고, 걷힘 대신 0.2초 엇갈림
  - 숫자(시간 · 두께 · 문구가 바뀌는 때)는 `lib/image/cutout-motion.ts` 맨 위 `CUTOUT_LOADING` 한 곳
  - 그사이 저장하기를 누르면 알약이 "다 지우면 바로 넘어가요"로 바뀌고, 다 지우면 걷힘을 빠르게(0.7배) 보여주고 누끼를 0.32초 보여준 뒤 저절로 정보 입력으로 넘어간다 (기다리는 동안 저장하기 · 보정은 잠김)
  - 그사이 배경제거를 끄면 원래 사진이 바로 보이고 저장도 바로 된다. 지우기는 뒤에서 끝까지 해 두어서 다시 켜면 기다리지 않는다
- **못 지우면(모델을 못 받는 등) 원래 사진으로 두고**, 버튼을 끈 상태로 바꾸고, 사진 아래쪽에 "배경을 지우지 못했어요 · 원래 사진으로 저장돼요"를 띄운다. 배경제거를 다시 누르면 다시 해 본다. 지우는 중에 저장하기를 눌렀다가 못 지웠으면, 넘어가지 않고 이 알림과 함께 머문다 — 한 번 더 누르면 원래 사진으로 저장
- **누끼 손질** — 배경을 지운 사진이 보일 때 사진 아래 "손질" 알약(지우개 아이콘). 누르면 검은 손질 화면이 덮인다(× 취소 · 제목 "손질" · 완료).
  - 사진은 체크 무늬 위에 보여 지운 곳(투명)이 보인다. **지우기**(덜 지운 곳을 지움) / **살리기**(너무 지운 곳에 배경제거 전 원래 사진의 색을 다시 채움) — 고른 쪽이 흰 채움. 붓 크기 세 단계(화면 지름 16 · 32 · 56px, 확대하면 사진 위에서는 그만큼 가늘어짐), 되돌리기(20획), "처음 누끼로"(자동으로 지운 결과로, 이것도 되돌릴 수 있음)
  - 한 손가락은 칠하기, 두 손가락은 확대(최대 8배) · 이동. 두 번째 손가락이 닿으면 칠하던 획은 취소한다. 컴퓨터는 마우스로 칠하고 휠로 확대. 칠하는 곳은 `touch-action: none` 이라 화면이 스크롤 · 확대되지 않는다
  - 손가락에 가리지 않게 붓 크기 원(검정 + 흰 두 겹)을 띄우고, 칠하는 동안 손가락 반대쪽 위 구석에 붓 자리를 2배로 키운 돋보기(112px)를 띄운다
  - 붓 가장자리는 부드럽다(안쪽 60% 꽉, 바깥 40% 점점). 손가락이 빨라도 반지름 1/4 간격으로 이어 칠한다. 계산은 `lib/image/retouch.ts`, 사진은 배경제거 결과 크기(긴 변 640) 그대로라 큰 사진에서도 가볍다
  - **폰 뒤로 가기는 손질만 닫는다**(2026-10-21 당니님). 사진 편집은 그대로 남고, 칠한 것은 완료처럼 남긴다(묻지 않는다 — 가장자리를 쓸다 뒤로 가기가 되어도 잃지 않게. × 는 그대로 이번 것을 버린다). 손질을 열 때 같은 주소로 이력을 한 칸 쌓고, × · 완료도 그 칸을 빼며 닫아 닫은 뒤의 뒤로 가기가 헛돌거나 손질을 다시 열지 않는다(`useHistoryLayer`, 규칙 `lib/history/layer.ts`)
  - 순서는 **배경 지우기 → 손질 → 보정**. 손질한 결과는 배경제거를 껐다 켜도 남는다(배경은 사진마다 한 번만 지우므로 덮이지 않는다). 다른 사진을 찍으면 처음부터. 원본은 언제나 찍힌 그대로
- 배경을 지운 것은 썸네일뿐이다. 원본은 언제나 찍힌 그대로 보관한다 (CLAUDE.md 규칙 7)
- 저장하기 → M-08. 배경제거를 끄고 저장해도 된다
- 뒤로(‹) → 왔던 곳. 촬영 화면에서 왔으면 다시 찍을 수 있다
- 사진 없이 들어오면(새로고침 등) 인벤토리로 돌려보낸다
- 인벤토리 만들기(M-03)도 같은 화면을 쓴다

**사진 아래에 색 보정이 있다** — 어두운 데서 찍으면 노란색이 녹색이 되는 식으로 색이 틀어지기 때문.

- **자동 보정** 알약 버튼. 누르면 켜지고(흰 채움) 다시 누르면 꺼진다. 기본은 꺼짐. 사진의 밝기 분포(히스토그램)를 보고 ① 화이트밸런스(중간 톤의 옅은 색 픽셀 평균이 회색이 되게, 70% 만) ② 레벨(밝기 하위 · 상위 0.5% 를 검정 · 흰색으로, 검정 60 · 흰색 170 까지만) ③ 감마(중앙값을 0.45 근처로, 어둡게는 1.2 까지만) ④ 대비(밝기가 좁게 몰린 사진만 조금)를 정한다. 계산은 `lib/image/adjust.ts`
- **세부 조정 ⌄** 를 누르면 그 아래에 슬라이더 넷이 펼쳐진다 — 밝기 · 대비 · 색온도(파랗게 ↔ 노랗게) · 색조(녹색 ↔ 자주색), 모두 -100 ~ 100, 기본 0. "세부 조정 되돌리기"로 0 으로. 자동 보정 위에 더해진다
- 흑백 톤만 쓴다 (포인트 색 없음)
- **보정은 칸에 보일 사진(썸네일)에만 입힌다. 원본은 찍힌 그대로 보관한다** (CLAUDE.md 규칙 7). 보정하지 않았으면 사진은 지금처럼 그대로 넘어간다
- **배경제거와의 순서: 배경은 보정 전 사진에서 지우고, 보정은 그 위에 입힌다.** 보정은 픽셀마다 따로 바뀌는 표(LUT)라 어느 쪽을 먼저 해도 물건의 색은 같다. 이렇게 하면 슬라이더를 밀 때마다 배경을 다시 지우지 않아도 되고(처음 20초), 자동 보정 값은 배경을 지우기 전 사진 전체로 한 번 정해서 배경제거를 껐다 켜도 색이 바뀌지 않는다. 지운 자리(투명)는 보정하지 않는다

**글쓰기 · 그리기는 뺐다.** 칸이 작아서 그 위의 글씨나 낙서는 알아볼 수 없고, 꾸미는 일은 INMYIN 에디터(M-09)의 몫이다. 등록은 빨라야 한다. 다시 넣을지는 `docs/roadmap.md`의 "나중에 할 일"에 적어 두었다.

주소는 `/my/inventories/[id]/items/new`, 화면 제목(브라우저 탭)과 헤더 가운데 글자는 "아이템 넣기"(2026-10-21 당니님 — 메뉴 · 빈 화면 버튼과 같은 말), 아래 버튼은 "저장하기" 그대로. 어두운 화면이고 하단 탭이 없다. 사진은 앞 단계에서 이미 골랐기 때문에 이 화면에는 나오지 않는다 — 새로고침으로 사진을 잃으면 인벤토리로 돌려보낸다.

**맨 위 "넣을 곳" 줄** (무늬 인벤토리고르기설계 v01 2절, 2026-10-20 당니님 결정). 여기가 저장 단계라 어느 인벤토리에 넣을지 여기서 고른다. 태그 칩이 인벤토리에 달려 있어서 맨 위다.
- 줄: 인벤토리 사진 32 · 이름 · `12/25`(이번 것을 더하기 전) · ⌄ — 입력칸과 같은 높이 · 바탕. 누르면 아래에서 **"넣을 곳" 판**이 올라온다(인벤토리 가져오기와 같은 틀 · 같은 줄 `InventoryChoiceRow`). 인벤토리가 하나뿐이면 ⌄ 없이 글자만
- 판: 인벤토리 관리와 같은 순서(고른 것을 맨 위로 올리지 않는다), 고른 줄은 회색 바탕 + 끝 ✓, 담긴 인벤토리는 "데스크 안", 꽉 찬 것은 흐리게 + "칸이 가득 찼어요"(못 누름). 누르면 바로 고르고 닫힌다. ↑↓ · Enter · Esc. 판 안에 다른 화면으로 가는 길은 없다 — 사진을 잃는다. 새 인벤토리도 여기서 만들지 않는다
- 처음 골라진 곳 = 주소의 `[id]`(인벤토리 + 면 그 인벤토리, 하단 탭 + 면 `/add` 가 고른 곳). `[id]` 가 그사이 꽉 찼으면 빈 칸 있는 다른 곳, 그것도 없으면 그대로 두고 줄 아래 "칸이 가득 찼어요 · 프리미엄으로 늘리기" + 저장 버튼 꺼짐
- 바꾸면 태그 칩이 새 인벤토리의 태그로 바뀐다. 입력칸에 적힌 글자는 그대로(저장하면 새 인벤토리 태그에 더해진다)
- 모아보기(M-13)에서 칩을 고른 채 왔으면(`?category=`) 태그 입력칸에 미리 채워져 있다
- 저장하는 순간 꽉 찼으면(다른 기기에서 채움) "데스크는 칸이 가득 찼어요. 다른 인벤토리를 골라 주세요." + 판이 열린다. 사진 · 글자는 그대로
- 아이템 수정(`/items/[itemId]/edit`)에는 이 줄이 없다 — 옮기기는 짐싸기의 몫

유통기한 아래에 한 줄: **"획득날짜와 유통기한은 비워 두면 아이템 상세에 나오지 않아요."** 아이템 상세(M-14)는 적힌 것만 보여주기 때문이다.

**달력은 투명한 날짜 칸을 아이콘(유통기한은 칸 전체) 위에 올려서 연다.** 아이폰은 손가락이 날짜 칸을 직접 눌러야만 달력을 띄운다 — 다른 버튼이 코드로 대신 열어 주는 방식은 컴퓨터에서만 된다.

저장하면 **고른** 인벤토리의 상세(M-04)로 가서(모아보기에서 왔어도) 새로 들어간 칸으로 스크롤하고, 그 칸이 "톡" 하고 나타난다 (M-04 "추가 직후 처리").

## M-09 ~ M-11 · INMYIN 에디터

빈 캔버스에 올릴 수 있는 것: 내 인벤토리 속 아이템(배경 제거된 썸네일), 갤러리 사진, 스티커.
조작: 확대·축소, 회전, 위치 이동.

이미지 캡처(M-10) → 갤러리 저장 또는 포스팅(M-11).

### M-09 · 에디터

주소는 `/my/inmyin/new`. 내 프로필(M-01)의 INMYIN 줄 오른쪽 **만들기**에서 온다. 하단 탭이 없다. 폰은 화면 높이를 다 쓰고 페이지는 스크롤하지 않는다 (짐싸기와 같다).

- 헤더미니(뒤로 → 프로필 · "INMYIN") 오른쪽에 버튼 **넷**: **되돌리기 · 추가(＋) · 전부 지우기(휴지통) · 완성(캔버스 카드 + 체크, → M-10)**. 그림은 아이콘 세트 v01(2026-10-20 무늬가 직접 그림, 하단 탭 세트와 같은 24 칸 · 선 1.75, `Icon.tsx`), 아이콘 밑 2px 에 11px 회색(ink-muted) 이름 — `aria-label` 도 같은 말. 비활성이면 아이콘 · 이름이 함께 흐려진다(.3). 전부 지우기는 묻지 않는다 — 되돌리기로 돌아올 수 있고 토스트가 그렇게 알린다. 피그마에는 스티커 · 사진 아이콘이 따로 있었지만 텍스트 · 배경까지 더하면 헤더에 안 들어가서 **＋ 판 하나**로 모았다 — 인스타 스토리처럼. 아이콘은 더 늘리지 않는다
- **＋ 판** (`AddSheet`) — 아래에서 올라오는 판, 맨 위 갈래 칩 **틀 · 스티커 · 사진 · 텍스트 · 배경** (홈 갈래와 같은 모양). 판 뒤는 살짝만 어두워서 배경을 고르며 캔버스를 본다. 에디터에 들어오면 판이 **틀** 칩이 열린 채 올라오고, 캔버스가 비어 있을 때 ＋ 를 눌러도 틀 칩부터
  - **틀** (`TemplatePicker`, `lib/inmyin/templates.ts`, 2026-10-20 당니님 결정 · 무늬 틀 설계서 v01): **A 가방 열기 · B 목록**. 칩은 회색 자리로 그린 84px 썸네일 + 이름. 고르면 판이 닫히고 배경이 그 틀 바탕(A 회색 #f2f2f2 · B 흰색)으로, 글자와 아이템 자리가 잡힌다. 되돌리기 한 걸음
    - 처음 고르면 캔버스에 올려 둔 **아이템을 모두 자리로**(올린 순서대로, 첫 아이템이 A 의 가방). 틀이 있는 채로 서랍에서 누르는 아이템은 다음 자리로 — 칸 · 부채가 개수에 맞춰 다시 잡힌다(구멍 없음). 틀 아이템을 지우면 뒤 아이템이 당겨진다. 사진 · 스티커는 자리에 넣지 않는다
    - 자리 수(A 10 · B 16)를 넘친 아이템은 가운데에 쌓이고, 틀을 고를 때마다 한 번 "이 틀은 자리가 N개예요. 나머지는 직접 놓아 주세요."
    - 손으로 옮기거나 키우거나 돌린 것, 고친 글자는 틀 표시가 떨어져 다시 건드리지 않는다(틀을 바꿔도 그 자리). B 아이템을 옮기면 그 이름 · 번호 글자도 같이 따라간다. 틀이 쓴 글자를 지우면 다시 쓰지 않는다
    - 다른 틀로 바꾸면 틀이 놓은 것만 새 자리로. 같은 틀을 다시 누르면 아무 일 없음
    - 글자: A "What's in my bag"(영어 유지) + 둘째 줄 **인벤토리 이름**(설계서의 "@아이디" 자리). B 제목 = 인벤토리 이름(왼쪽 끝 맞춤) · "아이템 N"(오른쪽 끝) · 칸마다 번호 "01" · 아이템 이름 자동. 인벤토리 이름은 첫 자리 아이템이 든 인벤토리, 아이템이 없으면 서랍의 첫 인벤토리. 왼쪽 · 오른쪽 맞춤은 캔버스가 글자를 잰 뒤 x 를 다시 맞춘다
    - 아이템은 누끼의 투명 여백을 뺀 보이는 물건을 자리 상자에 맞춘다(`lib/inmyin/visible-box.ts`, 데모 게시물과 같은 기준)
    - **빈 자리** — 틀만 고르고 아이템이 없을 때 미리 보기 개수(A 가방 + 5 · B 6)만큼 점선 회색 판. 이미지로 만들 때는 숨긴다. 아이템이 하나라도 들면 칸이 개수에 맞춰 잡혀 빈 자리가 없다
    - 크기 · 간격 · 기울기 · 색 · 문구는 `lib/inmyin/templates.ts` 맨 위 `TEMPLATE_NUMBERS` 한 곳 (당니님 조정용). 고친 뒤 `npm run test:template`
  - 스티커: 6열 격자 (아래 "스티커")
  - **사진** (`PhotoEditorSheet`): "갤러리에서 고르기" → 고르면 같은 칸에서 다듬는다 — 바둑판 위 미리보기 · **배경 지우기**(아이템 등록의 `removeBackground` 그대로, 처음 한 번 20초쯤) · **모양**(원본 · 원 · 네모 · 둥근 네모 · 하트 — 가운데를 정사각으로 잘라 그 모양만 남긴 PNG) · 다른 사진 · 올리기. 미리보기는 CSS 로 흉내 내고 올릴 때 진짜로 자른다(`lib/inmyin/photo-shape.ts`). 캔버스 폭(1080)까지 줄여서 올린다
  - **텍스트** (`TextEditor`): 위에 미리보기 → 글자(100자) → **글꼴** 칩(각각 그 글꼴로 보인다: 기본(본문과 같은 Wanted Sans, `app/fonts`) · 주아 · 도현 · 나눔손글씨 · 개구 · 고운바탕 · Dancing · Great Vibes · Pacifico — 전부 SIL OFL, `next/font/google` 로 우리 서버에서 내보낸다, `lib/inmyin/fonts.ts`) → 크기(작게 · 보통 · 크게 = 48 · 72 · 108) · 굵게 · 테두리 · 바탕 → 글자색 · (테두리색) · (바탕색) → 올리기. 캔버스 위 직접 타이핑은 폰에서 까다로워 판에서 한다. 캔버스에서는 손잡이로 키우면 글자 크기(fontSize)가 바뀐다(뭉개지지 않게). 올린 글자를 고르고 다시 누르면 메뉴에 **글자 고치기**가 생겨 같은 판이 열린다. 글꼴이 다 불린 뒤 다시 재서 테두리 · × 가 맞는다
  - **배경**: 종류 칩 **단색 · 선형 · 원형 · 하트 · 패턴** → 패턴이면 무늬 칩(점 · 줄 · 격자 · 체크), 선형이면 방향 칩(↓ ↘ → ↗) → 색 한 줄(단색) 또는 두 줄(안쪽/바깥, 바탕/무늬). 누르는 즉시 캔버스 바닥에 칠해진다.
  - **색 고르기** (`ColorField`, 배경 · 글자 공용): [지금 색 — 누르면 브라우저의 색상 선택기(아이폰은 스펙트럼 · 슬라이더 · 스포이드)] [헥스 코드 칸] [자주 쓰는 색 6개]. 처음엔 견본 18개를 늘어놓았는데 주인이 "너무 많아 어지럽다"고 해서 이렇게 바꿨다. 주인이 레이아웃을 그려 주면 그것에 맞춘다 그라디언트 · 패턴은 그림 파일 없이 캔버스가 그린다(`Background.tsx`) — 하트 그라디언트는 크기가 다른 하트 40장을 겹쳐 만든다. 연달아 고른 배경은 되돌리기 한 걸음. 전부 지우기는 물건만 지우고 배경은 남긴다
- **캔버스** — 흰 판, 옅은 테두리. 비율은 **4:5 세로**(저장은 1080×1350 기준). 피그마는 2:3 이었는데 폰에서 고르기 판 자리가 좁고 인스타에 올리면 잘려서 4:5 로 정했다. 캔버스 상자에 맞춰 크기가 정해지고(폭이 남으면 높이에, 높이가 남으면 폭에), 좌표는 늘 1080×1350 기준으로 적는다 — 폰에서 만든 것을 웹에서 열어도 같다
- 캔버스 위의 것: 누르면 골라진다 — **검은 테두리 2px · 모서리 흰 네모 손잡이(키우기, 비율 유지) · 위의 손잡이(돌리기, 0·90·180·270 에 살짝 붙는다) · 오른쪽 위 ×(지우기)**. 누르는 순간 골라져서 바로 끌 수 있다. 이미 고른 것을 끌지 않고 눌렀다 떼면 **"맨 뒤로 보내기 / 맨 앞으로 보내기"** 메뉴. 빈 곳을 누르면 풀린다. 40개까지
- 새로 올린 것은 캔버스 가운데에 긴 변이 폭의 40% 크기로, 여러 개면 조금씩 비껴 놓는다
- **되돌리기** — 올리기 · 옮기기 · 키우기 · 돌리기 · 지우기 · 순서 · 전부 지우기 모두 한 걸음씩 되돌린다 (50걸음). 그래서 전부 지우기는 따로 묻지 않는다
- **스티커** — ＋ 판의 첫 칩, 6열. Noto Color Emoji 그림 40개 (`public/stickers/`, `lib/inmyin/stickers.ts`). 폰의 이모지 글꼴로 찍지 않는다 — 기기마다 그림이 다르고 애플 글꼴은 이미지로 뽑아 배포할 수 없다
- **사진** — 갤러리(컴퓨터는 파일 고르기)에서 하나. 캔버스 폭(1080)까지 줄여서 올린다. 올리기 전까지는 브라우저 안의 주소(blob:)이고 포스팅(M-11)할 때 저장소에 올린다
- **아이템 고르기** (`ItemPicker`) — 폰은 캔버스 아래 42%, 웹은 오른쪽 478px 기둥. 인벤토리 띠 → 이름 줄 **"데스크 3/25"**(인벤토리 이름 13px 600 + 든 아이템 수 / 칸 수 회색 — 전에는 서랍 바닥의 흰 알약이라 캔버스 개수로 읽혔다) → 그리드/리스트 토글 + 태그 칩(전체 + 그 인벤토리의 태그) → 칸(짐싸기 칸과 같은 부품, 누르면 올라간다). 담긴 인벤토리는 올릴 수 없어 빠진다. 이미 캔버스에 올라간 아이템의 칸은 회색 테두리
- 저장 형태(`lib/inmyin/canvas.ts`): `{ version: 1, width: 1080, height: 1350, background: { kind: color|gradient|pattern, … }, objects: [그림 { id, kind: item|photo|sticker, itemId?, src, x, y, width, height, rotation } | 글자 { id, kind: text, text, font, fontSize, fill, bold, stroke, background, x, y, width, height, rotation }], template?: { id: A|B, detached: [글자 key] } }`. 틀이 놓은 개체에는 `template` 표시(아이템 `{ role: item, slot }` · 글자 `{ role: text, key, ax, ay, anchor }`)가 붙고 손대면 떨어진다. 이것이 `InmyinPost.canvasJson` 이 되고, `PostItem` 의 탭 영역은 `kind: item` 인 것에서 나온다
- 아직 없는 것: 두 손가락 집기(핀치)로 키우기 · 돌리기 — 손잡이로만 된다. 써 보고 불편하면 넣는다

### M-10 · 이미지 캡처

에디터의 **이미지 만들기**(헤더 맨 오른쪽)를 누르면. 같은 주소 안에서 화면만 바뀐다 — 캔버스는 그대로 남아 있어서 × 로 돌아가면 이어서 고친다. 캔버스에 아무것도 없으면 "올린 뒤 만들어 주세요".

- 손잡이를 풀고 캔버스를 통째로 **1080×1350 JPG** 로 뽑는다 (Konva `toDataURL`, 품질 0.92). 배경(단색 · 그라디언트 · 패턴)까지 그대로
- 헤더미니(× → 에디터 · "INMYIN") · 옅은 회색 바탕 · 흰 카드(4:5, 둥근 모서리, 옅은 테두리)에 이미지 · **포스팅 하기**(흰 바탕 + 회색 테두리 알약) · **JPG 이미지 저장하기**(검정 알약)
- JPG 저장 — 폰은 공유 시트(사진에 저장 · 카톡 · 에어드롭…), 공유 시트가 없는 컴퓨터는 내려받기 (`inmyin.jpg`)

### M-11 · 포스팅

M-10 의 포스팅 하기에서. 피그마 M-11.

- 헤더미니(× → M-10) · **제목** 한 줄(필수, 40자, 굵은 큰 글씨, 아래 선) · 흰 카드에 이미지 + **아이템 이름 라벨**(반투명 검정, 그 아이템의 가운데) · **내용**(선택, 500자) · **등록하기**(검정 알약)
- 등록하면 브라우저가 저장소(`posts` 버킷, `<유저 id>/<게시물 id>.jpg`)에 완성 이미지를, 캔버스에 올린 갤러리 사진도 같은 폴더에 올린 뒤 서버(`createPost`)가 `inmyin_posts` 한 줄과 `post_items`(탭 영역 — 캔버스에 대한 비율 0~1, 같은 아이템을 두 번 올렸으면 큰 쪽)를 적는다. 끝나면 내 프로필(M-01)로 — INMYIN 줄에 게시물 카드(4:5, 한 화면에 셋)가 늘어선다. 카드를 눌러 상세(H-04)로 가는 것은 그 화면을 만들 때
- 라벨의 "아이템 설명" 한 줄은 아직 없다 (이름만) — 고르기 판이 설명을 안 갖고 있다. H-04 에서 필요하면 그때

저장 형태:

```
InmyinPost {
  imageUrl     // 납작된 최종 이미지 (피드 노출용)
  canvasJson   // 개체 목록 + 위치/크기/회전 (재편집용)
}
PostItem[] { postId, itemId, x, y, w, h }   // 탭 영역
```

## 웹(데스크톱) 레이아웃

폰과 웹은 **1024px(`lg:`)** 에서 갈린다. 같은 주소 · 같은 부품이고 놓는 자리만 다르다 — 웹에 기능이 더 있지 않다 (CLAUDE.md 규칙 5). 피그마의 웹 화면은 `claudecode-master/web-layout/` 에 PNG 로 있다.

- **상단 메뉴** (`WebNav`) — 하단 탭 대신. 로고 · 홈 · 발견 · 북마크 · 프로필, 고른 것에 밑줄. 이름과 갈 곳은 하단 탭과 같다. 내용은 가운데 1200px (`max-w-web`, 2026-10-20 930 → 1200)
- **홈 · 북마크** — 갈래 줄(아이템 · INMYIN / 아이템 · INMYIN)은 폰과 같은 자리. 그 아래 한 줄에 [칩 …][검색칸][토글] (`ListControls`; 폰은 [토글][검색칸] + 칩 줄). 격자는 **7칸, 1280 이상은 8칸** (설정의 3/4칸은 폰에만). INMYIN 카드는 5칸 → 1280 이상 6칸, 발견은 2열 → 3열
- **프로필 틀** (`ProfileShell`, M-01 · H-06) — 프로필 줄(사진 · 아이디 · 닉네임 · 팔로워/팔로잉, 오른쪽 위 톱니 또는 ⋮, 오른쪽 아래 버튼 둘) 아래 **인벤토리 · 아이템 · INMYIN** 탭. 탭의 몸통(프로필 격자 · 모아보기 · INMYIN 카드)은 회색 판(`bg-gray-1`) 안에, 격자는 7칸(1280 이상 8칸). 폰도 같은 순서(프로필 줄 · 탭이 폰에도 있다). 짐싸기는 웹에서만 이 틀을 두른다
- **짐싸기** — 두 판을 나란히, 오른쪽 위 "완료"
- **팔로워 · 팔로잉** — 폰은 화면(M-12), 웹은 가운데 작은 모달(M-12a). 숫자를 누를 때 화면 너비로 가른다 (`FollowCounts`)
- **"+ 추가"** (`WebNavAdd`, 로그인했을 때만) — 상단 바 오른쪽, 로그아웃 왼쪽 24. 검정 알약(높이 36 · + 20 · "추가" 15 굵게) — 상단 바의 유일한 검정 채움. 누르면 + 메뉴와 같은 반투명 검은 메뉴 **아이템 넣기** · **INMYIN 만들기**. 키보드로 열고(Enter · Space) ↑↓ 로 고르고 Esc 로 닫는다(닫으면 포커스는 알약으로 — `DarkMenu` 공통). 꽉 참 · 인벤토리 없음은 여기서 묻지 않고 `/add` 가 정한다
- **아이템 넣기** — 컴퓨터에서 아이템 넣기(+ 칸 · 모아보기 + · 상단 "+ 추가")를 누르면 촬영 화면 대신 사진 고르기 창이 바로 열리고 편집(M-07)으로 간다(`useAddItem`). 넣을 곳은 정보 입력(M-08)에서
- 웹 그림이 없는 화면(설정 · 로그인 · 가입 · 정보 입력 · 약관 · 아이템 상세)은 폰 모양을 가운데 좁게(448px) 놓는다. 상단 메뉴는 로그인한 화면 어디에나 있다

## M-12 · 팔로워 · 팔로잉 목록 (내 · 타인 공용)

주소는 `/u/[아이디]/follows` (팔로워), `?tab=following` (팔로잉). 프로필(M-01 · H-06)의 팔로워 · 팔로잉 숫자를 누르면 온다. 하단 탭이 없다.

- 헤더: 뒤로(왔던 곳으로) · 제목은 그 사람의 닉네임
- 두 갈래 **팔로워 n · 팔로잉 n** — 홈의 갈래와 같은 모양(고른 쪽에만 밑줄)
- 줄: 프로필 사진 · 닉네임 · @아이디 · 오른쪽에 **팔로우 / 팔로잉** 버튼. 나 자신의 줄에는 버튼이 없다. 여기서 바로 걸고 풀 수 있다
- 팔로우 버튼은 어디서나 같다 (`FollowButton`): 안 걸었으면 검정 "팔로우", 걸었으면 흰 바탕 테두리 "팔로잉" — 누르면 화면부터 바뀌고 서버에 저장, 실패하면 되돌린다
- **웹(1024px 이상)에서는 이 화면 대신 모달(M-12a)이 뜬다** — 가운데 작은 창, × · 아이디 · 두 갈래(숫자 위 이름 아래) · 줄마다 팔로우 버튼 · 줄을 누르면 그 사람 프로필. 내용은 열릴 때 서버에서 받는다

## M-13 · 아이템 모아보기

인벤토리 구분 없이 아이템 전체를 최신순으로 본다. 내 프로필과 타유저 프로필 양쪽에 있다.

내 것의 주소는 `/my/items`. 프로필의 **아이템 탭**이다 — 프로필 줄 · 세 탭 아래에 펼쳐지고 하단 탭이 있다.

위에서부터: 프로필 줄 · 세 탭 → **그리드/리스트 토글 + 검색칸**(토글이 왼쪽 — 써 보니 그쪽이 편했다, M-04 와 같은 자리) → 태그 칩 한 줄 → 목록 위 왼쪽 `3/125` → 격자 또는 리스트.

- **검색과 태그는 누르는 즉시 걸러진다.** 들어올 때 아이템을 한 번에 다 읽어 두고 브라우저에서 거른다. 검색은 아이템 이름에서 찾는다
- **태그 칩은 모든 인벤토리의 태그를 이름으로 합친 것**이다. 맨 앞은 전체, 그 뒤로는 **아이템이 많은 태그부터** — 쓸어 넘기지 않아도 대부분 해결되게. 고른 칩을 한 번 더 누르면 전체로 돌아간다
- **리스트 보기에서는 이름 아래에 어느 인벤토리에 있는지**를 적는다. 인벤토리 구분 없이 보는 화면이라 "어디에 뒀는지"를 여기서 알려준다
- 아이템을 누르면 상세(M-14)로 간다. 수정 · 삭제는 거기의 ⋮ 메뉴로 한다 (이 화면에는 길게 누르기 · 밀기가 없다)
- 목록 위 숫자(작은 회색)는 평소에는 `내 아이템 수 / 넣을 수 있는 전체 칸 수`, 거르고 있을 때는 찾은 개수(`2개`)다
- **내 것에는 + 가 있다** (2026-10-20 당니님 결정). 격자 맨 뒤에 인벤토리와 같은 + 칸(리스트는 맨 아래 + 줄). 떠 있는 검정 + 는 없다(2026-10-21 당니님 — 하단 탭 + 와 둘이 나란히 보여서 뺐다, M-04 와 같다). 메뉴 없이 바로 아이템 넣기 — 하단 탭 + 와 같은 `/add` 를 거쳐 촬영(폰) · 사진 고르기(컴퓨터). **칩을 골라 둔 채 누르면** 그 태그 아이템이 가장 많은 인벤토리가 골라져 있고 태그도 채워져 있다. 검색 중에는 + 를 숨긴다(결과 끝의 + 는 "검색 결과에 넣는다"로 읽힌다). 모든 인벤토리가 꽉 찼으면 + 대신 "칸이 가득 찼어요 · 프리미엄으로 늘리기". 남의 것 · 북마크에는 없다
- 아이템이 없으면 빈 가방 "아직 등록한 아이템이 없어요. 찍어 넣은 물건이 전부 여기에 모여요." + **아이템 넣기**(+ 와 같은 갈림)(남의 것은 "공개된 아이템이 아직 없어요."만), 찾는 것이 없으면 가방 없이 "찾는 아이템이 없어요." 비어도 숫자 줄은 남는다(한도 안내)

### 태그 칩의 줄 (M-04 · M-13 공용)

**목록 위에서 거르는 칩은 몇 개든 한 줄이고, 넘치면 손가락으로 옆으로 쓸어 넘긴다** (`components/ui/ChipRow.tsx`). 여러 줄로 접히면 태그 개수에 따라 목록의 시작 높이가 바뀌고, 정작 보려는 아이템이 밀려난다. 모아보기는 모든 인벤토리의 태그가 합쳐져서 수십 개가 될 수 있다.

- 오른쪽 끝을 흐리게 해서 "옆에 더 있다"는 것을 알린다. 맨 끝까지 넘기면 마지막 칩이 흐린 곳을 벗어난다
- **M-04 의 그리드/리스트 토글은 이 줄 밖에, 왼쪽에 고정되어 있다.** 칩만 토글의 오른쪽에서 넘어가고, 토글을 만나기 전에 왼쪽에서 부드럽게 가려진다 (옆으로 넘긴 뒤에만 왼쪽 끝이 흐려진다). 칩을 넘겨 본 뒤에도 보기 방식을 바로 바꿀 수 있어야 한다
- 고른 칩이 화면 밖에 있으면 보이는 곳까지 자동으로 데려온다. **고른 칩이 바뀌었을 때만** 한다 — 매번 하면 손가락으로 줄을 넘길 때마다 고른 칩 쪽으로 도로 끌려간다
- 맨 앞은 항상 전체
- **정보 입력 화면(M-08 · 인벤토리 만들기)의 태그는 다르다 — 지금처럼 여러 줄로 접힌다.** 거기는 거르는 곳이 아니라 전부 보고 고르거나 고치는 곳이라, 가로 스크롤에 숨으면 놓친다

## M-14 · 아이템 상세

주소는 `/items/[itemId]`. **주소에 인벤토리를 넣지 않는다** — 아이템은 짐싸기로 인벤토리를 옮겨 다니는데, 그때마다 주소가 바뀌면 안 된다. 하단 탭이 없다.

위에서부터: 헤더(닫기 × · 제목 "아이템" · ⋮ 메뉴) → 큰 정사각형 사진(칸과 같은 옅은 회색 바탕, 개수가 둘 이상이면 오른쪽 아래에 `× 8`) → 이름 → 설명 → `• 획득날짜 26.09.06` · `• 유통기한 26.12.31 까지` (있는 것만. 피그마에는 "획득일자"로 적혀 있지만 정보 입력 화면과 같은 "획득날짜"로 통일했다) → **같은 인벤토리의 칸들**.

- 닫기(×) → 이 아이템이 들어 있는 인벤토리(M-04)
- **아래의 칸들은 M-04 의 격자와 같은 순서다.** 지금 보고 있는 아이템에는 검은 테두리. 다른 칸을 누르면 그 아이템으로 건너간다. 빈 칸과 + 칸은 그리지 않는다
- **⋮ 메뉴 = 삭제하기 / 수정하기.** 리스트의 밀기 · 그리드의 길게 누르기(M-04)와 같은 일을 한다. 밀기를 모르는 사람이나 마우스를 쓰는 데스크톱에서도 찾을 수 있어야 해서 둘 다 둔다
- 삭제하면 인벤토리(M-04)로 돌아가고, 거기서 지운 자리에 "되돌리기" 칸이 뜬다. 자세한 동작은 M-04 의 "밀어서 수정 · 삭제"
- 제목 줄 오른쪽에 **하트 · 하트 수 · 댓글 · 댓글 수** — 내 아이템에 누가 얼마나 반응했는지 여기서도 본다. 북마크는 없다 (내 것을 모을 일이 없다). 홈에서 열면 H-02 모양이 되면서 북마크까지 보인다
- 칸들 아래, 맨 마지막에 **댓글** (H-02 와 같은 부품). 내 아이템이라 모든 댓글을 밀어서 지울 수 있다
- 이 모양은 **내 인벤토리에서 온 내 아이템**일 때다. 홈 피드에서 왔거나 남의 아이템이면 같은 주소에서 H-02 모양으로 열린다

## V-01, V-02 · 북마크 탭

북마크를 누른 것들이 모이는 탭. 주소는 `/bookmark`. 상단이 **아이템** / **INMYIN** 두 갈래 (`?tab=inmyin`). INMYIN 갈래(V-02)는 북마크한 게시물을 카드 격자(H-03 과 같은 부품)로, 최근에 누른 순, 격자 위 숫자는 `n개`. 비었으면 빈 가방 "책갈피를 누른 INMYIN이 여기에 모여요." + **INMYIN 구경하기**.

- 아이콘과 이름은 **책갈피**(Bookmark). 하트로 모으지 않는다 — 하트는 반응일 뿐이다
- 아이템 모아보기(M-13)와 같은 부품 — 검색칸 · 그리드/리스트 토글 · 태그 칩(맨 앞은 전체, 북마크한 것들의 태그를 많은 순으로). 브라우저에서 바로 거른다
- 격자 칸의 주인은 H-01 과 같이 웹에서 마우스를 올리면 프로필 사진 · 닉네임
- 최근에 누른 순. 리스트의 줄에는 **닉네임 · 인벤토리 이름** — 남의 것이 모이는 곳이고 내 인벤토리에 들어온 것이 아니라는 것이 여기서 드러난다
- 칩 줄 아래 한 줄: 왼쪽 숫자(작은 회색) · 오른쪽 **최신순 | 오래된순**. 비었으면 빈 가방 "책갈피를 누른 아이템이 여기에 모여요." + **홈 구경하기**
- 모을 수 있는 개수는 플랜 한도 (`lib/plans.ts` 의 `maxBookmarks`: 베이직 500 · 프리미엄 2,000). 차면 책갈피를 눌렀을 때 "북마크는 500개까지 모을 수 있어요". 목록 위 숫자는 `n/500`(거르는 중이면 `n개`). 그사이 비공개가 되거나 지워진 아이템은 사라진다 (DB 규칙)
- 아이템을 누르면 상세(H-02). 거기서 책갈피를 끄면 이 탭에서 빠진다

## N-01 · 알림

홈 갈래 줄 오른쪽 끝의 종에서 온다. 주소는 `/notifications`. 하단 탭은 홈이 켜진 채. 피그마 프레임은 없고 다른 목록 화면과 같은 모양으로 만들었다. 종 아이콘은 하단 탭과 같은 세트 v01 (2026-10-20).

- 헤더미니(뒤로 → 홈) · 제목 "알림"
- 줄 하나 = 왼쪽 동그라미(프로필 사진, 공지는 검은 원에 종) · 가운데 글 · 시각("5분 전", 일주일 지나면 날짜) · 오른쪽에 아이템 썸네일이나 팔로우 버튼. 최신순, 알림 100개 + 공지 20개까지
  - 팔로우: "**닉네임**님이 회원님을 팔로우하기 시작했어요" · 오른쪽 팔로우/팔로잉 버튼(맞팔). 누르면 그 사람 프로필
  - 하트: "**닉네임**님이 회원님의 아이템에 하트를 눌렀어요" · 오른쪽 썸네일. 누르면 그 아이템
  - 댓글: "**닉네임**님이 댓글을 남겼어요: (앞 40자)" · 오른쪽 썸네일. 누르면 그 아이템
  - 공지: "공지" · 제목 · 내용. 링크가 있으면 누르면 거기로
- **알림은 화면이 아니라 DB 트리거가 만든다** — 팔로우 · 하트 · 댓글이 생기는 순간 받는 사람에게 한 줄. 내 것에 내가 한 건 안 만들고, 취소(언팔로우 · 하트 끄기 · 댓글 삭제)하면 같이 사라진다. 같은 사람이 같은 것에 껐다 켰다 해도 알림은 하나
- 차단 사이의 사람이 한 알림은 안 보인다 (DB 규칙). 지워진 아이템의 알림도 빠진다
- **마지막으로 본 시각**(`users.notificationsSeenAt`)보다 새것은 옅은 바탕. 화면이 그려지면 "여기까지 봤다"고 적어(`MarkSeen`) 종의 빨간 점이 꺼진다. 한 번도 안 열었으면 가입 시각이 기준 — 가입 전의 공지는 새것이 아니다
- 푸시 알림(앱을 안 열어도 폰에 뜨는 것)은 4단계. 이 테이블에 새 행이 생길 때 보내는 한 겹만 얹으면 된다

### 공지 넣는 법 (주인이 직접)

코드를 고치지 않고 Supabase 대시보드에서 넣는다. 모두의 알림 목록 맨 위에 뜨고, 안 본 사람의 종에 빨간 점이 켜진다.

1. https://supabase.com/dashboard → INMYIN 프로젝트 → 왼쪽 메뉴 **Table Editor**
2. 표 목록에서 **announcements** 클릭
3. 위쪽 **Insert** → **Insert row**
4. `title`(제목, 필수) · `body`(내용, 선택) · `link`(누르면 갈 곳, 선택 — 예: `/my/settings`) 만 채우고 나머지는 비워 둔 채 **Save**
5. 지우려면 그 줄의 `deleted_at` 에 아무 시각이나 넣는다 (예: `now()`). 줄을 삭제하지 않는다 (규칙 6)
