# 화면 정의

피그마 파일 `인벤토리` 기준. 고유 화면 31개. 모바일 프레임이 기준이고, 같은 화면의 웹(데스크톱) 버전이 별도 프레임으로 존재한다.

## 하단 탭

```
1. Like (북마크 → Like로 이름 변경)   2. Home (커뮤니티)   3. My
```

왼쪽부터 이 순서로 놓인다. Home이 가운데다. 선택된 탭은 아이콘 속을 채우고, 글자는 그대로 둔다.

## 전체 목록

```
M-04 · 인벤토리 상세
M-04 · 인벤토리 상세 (웹)
```

## A-01 · 로그인

로그인하지 않은 사람이 앱에 들어오면 가장 먼저 보는 화면. 주소는 `/login`.

- 로고
- Google로 로그인 / Kakao로 로그인 — 처음이면 A-03, 아니면 홈으로
- 글자 링크 두 개: 이메일 가입 → A-02, 이메일 로그인 → A-01a
- 맨 아래: 이용약관 · 개인정보 취급방침 · 문의 메일
- 이미 로그인한 사람이 오면 홈으로 돌려보낸다

## A-01a · 이메일 로그인

주소는 `/login/email`. 피그마 프레임은 없고 A-02와 같은 모양으로 만든다.

- 이메일 + 비밀번호 (눈 아이콘으로 보기/숨기기) → 로그인
- 비밀번호 칸 아래에 글자 링크 **비밀번호를 잊으셨나요?** → A-04
- 아래에 이메일 가입(A-02), 다른 방법으로 로그인(A-01)

## A-02 · 가입

이메일 가입 전용. 구글·카카오는 가입 화면 없이 A-01에서 바로 A-03으로 간다. 주소는 `/signup`.

1. 이메일 입력 → **인증번호 전송** → 메일로 온 숫자를 입력 → **확인**. 남은 시간 3:00 표시, 다시 보내기는 60초 뒤부터
   - 맞으면 "인증번호가 확인되었습니다."가 뜨고 시간 표시가 사라지며 이메일·인증번호 칸이 잠긴다
2. 비밀번호 입력 (8자 이상, 눈 아이콘으로 보기/숨기기) — 인증번호를 확인한 뒤에 입력할 수 있다
3. 약관 동의 — "모두 동의합니다" + 개별 항목. 항목은 `lib/terms.ts`
4. **가입하기** → 비밀번호 + 약관 동의 저장 → A-03

인증번호를 보내기 전에는 인증번호 칸과 약관이 보이지 않는다 (가입1 → 가입2 프레임).

이미 가입한 이메일(비밀번호가 있거나 구글·카카오로 연결된 계정)이면 메일을 보내지 않고 "이미 가입한 이메일입니다. 로그인해 주세요."라고 알려준다. 인증번호만 받고 그만둔 사람은 다시 와서 이어갈 수 있다.

## A-03 · 프로필 만들기

첫 로그인 직후 한 번만 나온다. 주소는 `/onboarding`. 이걸 끝내야 `User` 행이 생긴다.

- 닉네임 — 구글·카카오 이름이 있으면 미리 채워둔다
- 아이디(`handle`) — 프로필 주소 `/u/아이디`가 된다. 영소문자·숫자·`_`, 3~30자, 중복 불가
- 구글·카카오로 들어와 아직 약관에 동의한 적 없는 사람에게는 여기서 약관 동의를 받는다
- **등록하기** → 홈

프로필이 없는 사람이 다른 화면으로 가려 하면 여기로 돌려보낸다.

## A-04 · 비밀번호 재설정

이메일로 가입한 사람이 비밀번호를 잊었을 때. 주소는 `/reset-password`. A-02와 같은 모양에서 약관만 뺀다.

안내문: "가입한 이메일을 입력하면 본인인증 후 비밀번호를 재설정할 수 있습니다."

1. 이메일 입력 → **인증번호 전송** → 메일로 온 숫자를 입력 → **확인**. 남은 시간·다시 보내기·확인 뒤 잠금은 A-02와 같다
2. **새 비밀번호** 입력 (8자 이상, 눈 아이콘으로 보기/숨기기) — 인증번호를 확인한 뒤에 입력할 수 있다
3. **비밀번호 변경하기** → 새 비밀번호 저장 → 로그인된 상태로 홈

- 가입하지 않은 이메일이면 메일을 보내지 않고 "가입하지 않은 이메일입니다."라고 바로 알려준다. 계정을 새로 만들지 않는다
- 가입한 이메일이 기억나지 않는 사람을 위해 맨 아래에 안내를 둔다: 구글·카카오로 가입했다면 로그인 화면의 해당 버튼으로, 그래도 못 찾으면 문의 메일로
- 아이디(`handle`)로 이메일을 찾아주는 기능은 없다 — 아이디는 공개 정보라 남의 이메일 힌트가 새기 때문

## H-01 · Home › 아이템

공개로 등록된 아이템을 최신순으로 뿌린다.

- 검색바
- 카테고리 필터 — 맨 앞은 항상 **전체**. 태그가 없는 아이템은 전체에서만 보인다. 태그가 유저마다 자유라서 나머지 칩을 어떻게 고를지는 2단계에서 정한다 (후보: 검색 + 많이 쓰이는 태그)
- 그리드 보기 ↔ 리스트 보기 라디오 버튼
- 카드 탭 → H-02

## H-02 · Home › 아이템 상세

할 수 있는 것: 좋아요, 작성자 프로필로 이동, 팔로우.

## H-03 · Home › INMYIN 목록

- 상단: 전체 + 주요 카테고리 몇 개
- 정렬: 인기순 / 최신순 (인기 = 최근 24시간 좋아요 수)
- 카드 탭 → H-04

## H-04 · Home › INMYIN 상세

게시물 이미지 위의 아이템 영역(hotspot)을 탭하면 그 아이템 상세(M-14)로 간다. 삭제된 아이템이면 이미지는 그대로 보이고 탭해도 아무 일도 일어나지 않는다.

## H-05 · Home › 발견

사람을 찾는 탭. 필터 두 개.

| 필터 | 대상 | 정렬 |
| --- | --- | --- |
| 인기 | 전체 유저 | 최근 24시간 좋아요 수 |
| 추천 | 누적 좋아요 100 미만인 유저 | 최근 1시간 좋아요 수 |

둘 다 유저의 INMYIN 게시물과 아이디·팔로우 버튼을 보여준다.

## H-06 ~ H-08 · 타유저 프로필

팔로우 버튼, 프로필 공유 버튼. 팔로우·팔로잉 숫자를 누르면 모달(M-12a)이 뜬다. 그 사람의 인벤토리 · 아이템 모아보기 · INMYIN 게시물을 구경할 수 있다.

**비공개 아이템은 아예 보이지 않는다.** 저장은 칸 번호 그대로 두고, 읽을 때만 공개 아이템을 모아 다시 줄을 세운다.

## M-01 · My › 내 프로필

모바일에서 My의 기본 화면. 여기서 설정 · 인벤토리 · INMYIN 에디터로 갈라진다.
**웹에서는 프로필과 인벤토리가 한 화면에 같이 나오는 게 기본이다.**

## M-03 · My › 인벤토리 목록

인벤토리를 추가하고 고르는 화면. 주소는 `/my/inventories`.

있는 인벤토리와 그 다음의 + 줄 하나만 그린다. **빈 자리는 그리지 않는다** — 어차피 + 가 항상 있다.

- 줄 하나 = 썸네일 칸 + 이름 + `n/25` (든 아이템 수 / 칸 수). 사진은 필수라 썸네일이 항상 있다
- **+ 줄은 마지막 인벤토리 다음에 하나만.** 옆에 "+를 눌러 인벤토리를 추가하세요."
- 줄을 누르면 그 인벤토리의 상세(M-04)로 간다. 줄을 밀면 수정 · 삭제 (방향은 M-04 와 같다)
- **인벤토리는 비어 있을 때만 삭제할 수 있다.** 아이템이나 다른 인벤토리가 들어 있으면 막고, 먼저 비우라고 안내한다
- 우측 위 `TOTAL 9/125` = 내 아이템 전체 수 / (인벤토리 한도 × 칸 수)
- 베이직: 5개까지, 판당 25칸 · 프리미엄: 20개까지, 판당 50칸
- 한도에 닿으면 + 칸이 사라지고 아래에 **인벤토리 늘리기** 버튼이 나온다 → 플랜 결제 화면 (4단계 전까지는 "준비 중" 안내)

### + 를 누르면

1. 작은 메뉴: **사진 업로드 / 사진 찍기**. 데스크톱에서는 메뉴 없이 바로 파일 고르기
2. 사진 편집 (M-07) — 주소는 `/my/inventories/new/edit`, 아이템 편집과 같은 화면이다
3. 인벤토리 정보 입력 → 저장하면 목록으로 돌아온다

사진 찍기는 촬영 화면(M-06)을 연다 — 주소는 `/my/inventories/new/camera`, 아이템 촬영과 같은 화면이다. 이 메뉴는 인벤토리 목록에만 있다 — 아이템은 빈 칸에서 이미 한 번 고르므로(M-04) 바로 촬영 화면으로 가고 거기서 갤러리를 고른다.

### 인벤토리 정보 입력

| 필드 | 필수 | 형태 |
| --- | --- | --- |
| 인벤토리 이름 | ● | 한 줄 텍스트 + 드롭다운. 드롭다운에는 추천 4종(옷장·냉장고·집·생활용품) |
| 카테고리 | | 태그 칩. 직접 써서 추가, ×로 삭제. 10개 · 한 개 10자까지 |

추천을 고르면 이름과 기본 태그가 채워진다. **지름길일 뿐이다** — 그 뒤로는 이름도 태그도 자유롭게 고친다. 추천을 다시 고르면 이름과 태그가 새 추천으로 바뀐다.

## M-04 · My › 인벤토리 상세

주소는 `/my/inventories/[id]`. **이 화면에는 하단 탭이 없다.**

위에서부터: 헤더(뒤로 · 제목 · 짐싸기 버튼) → 인벤토리 띠(내 인벤토리 썸네일을 가로로 늘어놓고, 보고 있는 것에 테두리. 누르면 그 인벤토리로 갈아탄다) → 그리드/리스트 토글 + 카테고리 칩(맨 앞은 전체) → 격자 또는 리스트 → 맨 아래 `16/25`.

채워진 칸을 누르면 아이템은 상세(M-14)로, 안에 담긴 인벤토리는 그 인벤토리로 간다.

\+ 칸을 누르면 메뉴가 뜨고, 두 가지로 채운다.

1. **새 아이템 등록** — 새로 사진 찍어 등록하기 → M-06. 데스크톱에서는 "휴대폰에서 등록해 주세요" 안내
2. **인벤토리 가져오기** — 다른 인벤토리를 통째로 이 칸에 담는다. 이미 다른 곳에 들어가 있는 인벤토리는 고를 수 없게 막는다

### 밀어서 수정 · 삭제

- **왼쪽으로 밀면** 오른쪽에서 보라색 휴지통이 나온다 → 삭제 (`deletedAt` 기록)
- **오른쪽으로 밀면** 왼쪽에서 회색 연필이 나온다 → 수정
- 줄의 내용은 움직이지 않는다. 너비 77 의 색 블록이 가장자리에서 줄을 덮으며 나온다. 반 넘게 나왔을 때 손을 떼면 끝까지 열리고, 아니면 닫힌다. 블록을 눌러야 실행된다 — 밀기만 해서는 지워지지 않는다
- 한 번에 한 줄만 열린다. 열린 채 줄을 누르면 상세로 가지 않고 닫힌다
- 밀기는 **리스트의 줄**에서 한다. 인벤토리 목록(M-03)의 줄도 같은 동작으로 인벤토리를 수정 · 삭제한다
- **그리드의 칸은 밀지 않고 길게 누른다.** 칸이 작아서 밀기가 어색하다. 0.5초 누르면 아이템 상세(M-14)의 ⋮ 와 같은 메뉴(삭제하기 / 수정하기)가 뜬다. 데스크톱에서는 마우스 오른쪽 버튼도 같은 메뉴를 띄운다
- **삭제는 확인 창 없이 바로 지우고, 지운 바로 그 자리가 7초 동안 "되돌리기" 칸으로 남는다.** 사진은 흐려지고, 보라색(point) 되돌리기 화살표와 글자가 나오고, 보라색 선이 7초 동안 남은 시간을 알려준다 — **그리드의 칸에서는 테두리를 따라 한 바퀴 돌며 지워지고** (위 가운데에서 시작해 시계 방향), **리스트의 줄에서는 아래의 선이 줄어든다.** 리스트의 줄에는 이름 아래에 "삭제했어요"가 붙는다. 7초가 지나면 그 칸이 사라지고 뒤의 칸들이 당겨 붙는다
  - **화면 아래에 뜨는 안내(토스트)로 하지 않는다.** 지운 자리와 멀고 어두워서 눈에 띄지 않았다. 되돌리기는 눈과 손가락이 이미 가 있는 곳에 있어야 한다
  - 되돌리면 맨 뒤가 아니라 **원래 있던 순서**로 돌아가고, 그 칸을 잠깐 강조한다
  - 되돌리기 칸은 눌러도 상세로 가지 않는다. 찬 칸으로 세지 않는다 (`16/25` 는 지운 즉시 줄어든다)
  - 7초 안에 다른 아이템을 또 지우면 앞의 것은 그대로 확정된다. 처음에는 5초였는데 조금 빠르게 느껴져서 늘렸다
  - **삭제도 되돌리기도 누른 즉시 화면부터 바뀐다.** 서버의 답을 기다리지 않는다 — 답이 늦으면 멈춘 것처럼 보이고, 기다리다 여러 번 누르게 된다. 서버에 알리는 일은 뒤에서 하고, 실패했을 때만 칸을 원래대로 돌려놓고 안내를 띄운다. 같은 요청이 두 번 와도(이미 지워짐 · 이미 살아 있음) 서버는 성공으로 답한다
  - **되돌리기 칸이 떠 있는 동안 다른 화면으로 넘어가도 된다.** 삭제는 누른 순간 이미 끝났고, 이 칸은 되살릴 기회일 뿐이다. 넘어가면 그대로 확정된다
- **수정은 정보 입력(M-08)과 같은 화면**에 지금 값을 채워서 연다. 헤더의 제목과 아래 버튼은 "저장하기"가 아니라 **"수정하기"**다. 주소는 `/items/[itemId]/edit`. 글자 정보만 고친다 — 사진 바꾸기는 나중에 할 일. 저장하면 아이템 상세(M-14)로 간다
- 칸 안에 담긴 인벤토리에는 이 동작이 없다. 인벤토리의 수정 · 삭제는 인벤토리 목록(M-03)에서 한다

**이미 등록된 아이템은 불러올 수 없다.** 실제 물건은 두 곳에 동시에 존재할 수 없기 때문이다. 옮기려면 짐싸기를 쓴다. 같은 이유로, 이미 다른 인벤토리 안에 들어가 있는 인벤토리도 또 불러올 수 없다. 한 줄로 이어지는 중첩은 5겹까지 (예: 집 › 방 › 가방 › 작은 가방 › 파우치).

### 새 아이템이 들어가는 자리

**항상 마지막 아이템의 다음 칸.** 첫 줄에 끼워 넣어 기존 아이템을 밀어내지 않는다. 새 것이 끼어들어 자리가 바뀌면 "어디에 뭘 뒀는지"라는 이 앱의 핵심 가치가 무너진다.

**중간에서 아이템을 지우면 뒤의 아이템들이 한 칸씩 당겨 붙는다.** 구멍은 남지 않는다. 짐싸기로 아이템이 빠져나간 자리도 마찬가지다.

추가 직후 처리:

- 새로 들어간 칸으로 자동 스크롤
- 그 칸이 움직여서 알려준다. **보라색 테두리를 번쩍이는 방식은 어색해서 버렸다**
  - 그리드의 칸: 작게(0.7배) 시작해 살짝 넘치게(1.06배) 커졌다가 제 크기로 돌아온다 — 홈 화면에 앱이 깔릴 때 같은 "톡". 0.5초
  - 리스트의 줄: 옅은 보라색이 깔렸다가 서서히 빠진다 — 목록에서 "방금 바뀐 줄"을 알릴 때 흔히 쓰는 방식. 1.4초
  - 새 칸이 화면 밖에 있으면 스크롤로 데려와서 **도착한 순간** 움직인다. 이미 눈에 보이던 칸은 사라졌다 나타나면 깜빡이므로, 그때는 제자리에서 한 번 부푼다(1.1배)
  - 삭제를 되돌렸을 때도 같은 움직임이다

**리스트 보기도 격자와 같은 순서**이고, + 줄이 맨 아래에 온다. 최신순으로 보고 싶을 때는 아이템 모아보기(M-13)를 쓴다.

### 추가 버튼

- **+ 칸은 마지막 아이템의 다음 칸에 하나만.** 아이템이 없으면 첫 번째 칸이다. 나머지 빈 칸은 그리지 않는다
- **+ 칸이 화면 밖으로 나가면 플로팅 버튼이 나타난다.** 화면 아래에서 16px, 우측 16px. 둘 다 결과는 같다 — 마지막 아이템 다음 칸에 추가
- **칸이 다 차면** + 칸 자리에 "칸이 가득 찼어요 · 프리미엄으로 늘리기"를 띄운다. + 를 그냥 없애면 기능이 사라진 줄 안다
- 하단에 `16/25` 같은 사용량 표시를 유지한다

### 칸 수에 따른 격자

| 칸 수 | 열 |
| --- | --- |
| 25 (베이직) | 3 |
| 50 (프리미엄) | 4 |
| 100+ | 5 |

**채워진 칸의 바탕은 옅은 회색(gray-1), + 칸의 바탕은 흰색이다.** 배경을 지운 사진은 옅은 회색 위에 물건만 놓인다. + 는 피그마 그림보다 굵기를 반으로 줄였다.

**빈 칸은 그리지 않는다.** 채워진 칸과 그 다음의 + 칸만 보인다. 인벤토리 띠에도 빈 칸을 두지 않는다. 남은 용량은 아래의 `16/25` 가 알려준다.

그리드/리스트 토글은 **검정 바탕에 흰 아이콘**이다 (피그마의 회색 바탕은 옆의 카테고리 칩과 섞여 보인다). 헤더 제목은 인벤토리 이름이 아니라 **"INVENTORY" 고정**이다 — 띠로 인벤토리를 오가는 화면이라 제목이 바뀌지 않는 편이 낫다.

## M-05 · 짐싸기

우측 상단 버튼 → 인벤토리 두 개가 동시에 열린다. 한쪽에서 아이템을 선택하면 반대쪽으로 넘어가고 즉시 자동 저장된다.

- 한 번에 하나씩만 옮긴다. 다중 선택 없음
- 되돌리기 버튼 없음 — 반대쪽에서 다시 누르면 돌아온다
- 받는 쪽이 꽉 찼으면 "○○가 꽉 찼습니다. 이동이 불가합니다" 알림을 띄우고 이동하지 않는다

## M-06 · 아이템 촬영

주소는 `/my/inventories/[id]/items/camera`. 화면 가득 카메라가 나오고 하단 탭이 없다.

위에 닫기(×)와 제목 "촬영모드", 가운데에 둥근 네모 프레임, 아래 가운데에 셔터, 그 왼쪽에 "갤러리에서 선택" 버튼. 실제 썸네일로 쓰일 영역(프레임) 밖은 어둡게 마스크 처리된다. 칸이 정사각형이라 프레임도 정사각형이다.

- **찍으면 사진이 두 장 만들어진다.** 프레임 안쪽만 잘라낸 것이 칸에 보이는 썸네일이 되고, 프레임 밖까지 찍힌 전체는 원본으로 보관한다 (CLAUDE.md 규칙 7)
- 갤러리에서 고른 사진은 프레임이 없으므로 자르지 않는다. 썸네일과 원본이 같은 사진이다
- 찍거나 고르면 편집(M-07)으로 간다
- 카메라 권한을 거절했거나 카메라가 없으면 프레임 안에 "카메라를 쓸 수 없어요" 안내를 띄운다. 갤러리 버튼은 그대로 쓸 수 있다
- 다른 앱으로 나가면 카메라를 끄고, 돌아오면 다시 켠다
- 카메라는 `https` 주소(와 개발용 `localhost`)에서만 켜진다 — 브라우저의 규칙이다
- 인벤토리 만들기의 "사진 찍기"(M-03)도 같은 화면을 쓴다

**웹에서는 이 화면이 없다.** 데스크톱에서는 등록 버튼 자리에 "휴대폰에서 등록해 주세요" 알림을 띄운다.

## M-07 · 아이템 편집

주소는 `/my/inventories/[id]/items/edit`. 검은 화면이고 하단 탭이 없다.

위에 뒤로(‹)와 제목 "사진편집", 오른쪽 위에 **배경제거** 버튼, 가운데에 사진, 아래에 **저장하기**. 사진은 칸과 같은 회색 바탕 · 같은 자르기(가운데 정사각형)로 보여준다 — 격자에서 어떻게 보일지 그대로다.

- **배경제거를 누르면 물건만 남는다 (누끼 따기).** 다시 누르면 원래 사진으로 돌아온다. 지운 결과는 기억해 두어서 껐다 켜도 다시 기다리지 않는다
- 배경을 지우는 일은 폰 안에서 한다 — 사진이 밖으로 나가지 않는다. **처음 한 번은 AI 모델을 내려받느라 오래 걸린다** (컴퓨터에서 20초쯤). 그동안 사진 위에 "배경을 지우는 중…"을 띄운다
- 배경을 지운 것은 썸네일뿐이다. 원본은 언제나 찍힌 그대로 보관한다 (CLAUDE.md 규칙 7)
- 저장하기 → M-08. 배경제거를 누르지 않고 저장해도 된다
- 뒤로(‹) → 왔던 곳. 촬영 화면에서 왔으면 다시 찍을 수 있다
- 사진 없이 들어오면(새로고침 등) 인벤토리로 돌려보낸다
- 인벤토리 만들기(M-03)도 같은 화면을 쓴다

**나중에 넣을 것은 색 보정(레벨 조정)이다** — 어두운 데서 찍으면 노란색이 녹색이 되는 식으로 색이 틀어지기 때문. 자세한 것은 `docs/roadmap.md`의 "나중에 할 일".

**글쓰기 · 그리기는 뺐다.** 칸이 작아서 그 위의 글씨나 낙서는 알아볼 수 없고, 꾸미는 일은 INMYIN 에디터(M-09)의 몫이다. 등록은 빨라야 한다. 다시 넣을지는 `docs/roadmap.md`의 "나중에 할 일"에 적어 두었다.

## M-08 · 아이템 정보 입력

| 필드 | 필수 | 형태 |
| --- | --- | --- |
| 아이템 이름 | ● | 한 줄 텍스트 (30자) |
| 설명 | ● | 여러 줄 텍스트 (300자) |
| 카테고리 | | 이 인벤토리에 달린 태그를 칩으로 보여주고 하나를 고른다. 없는 것은 입력칸에 직접 쓴다 — 저장할 때 이 인벤토리의 태그에도 더해진다. 고르지 않아도 된다 |
| 개수 | | 숫자 + 위아래 화살표. 1 ~ 999 |
| 획득날짜 | | **자유 글자 (20자).** "20살 생일"처럼 써도 되고, 달력 아이콘으로 날짜를 고르면 `26.09.22` 꼴로 채워진다. 안내 글자는 "획득날짜를 입력해 주세요." — 예시("20살 생일")를 넣으면 이미 적힌 값처럼 보인다 |
| 유통기한 | | 달력으로 고르는 날짜. `26.09.22 까지` 로 보인다. 안내 글자는 "날짜를 골라 주세요." 칸 어디를 눌러도 달력이 열린다 |
| 공개 | | 토글. 기본은 켜짐 |

주소는 `/my/inventories/[id]/items/new`. 어두운 화면이고 하단 탭이 없다. 사진은 앞 단계에서 이미 골랐기 때문에 이 화면에는 나오지 않는다 — 새로고침으로 사진을 잃으면 인벤토리로 돌려보낸다.

유통기한 아래에 한 줄: **"획득날짜와 유통기한은 비워 두면 아이템 상세에 나오지 않아요."** 아이템 상세(M-14)는 적힌 것만 보여주기 때문이다.

**달력은 투명한 날짜 칸을 아이콘(유통기한은 칸 전체) 위에 올려서 연다.** 아이폰은 손가락이 날짜 칸을 직접 눌러야만 달력을 띄운다 — 다른 버튼이 코드로 대신 열어 주는 방식은 컴퓨터에서만 된다.

저장하면 인벤토리 상세(M-04)로 돌아가 새로 들어간 칸으로 스크롤하고, 그 칸이 "톡" 하고 나타난다 (M-04 "추가 직후 처리").

## M-13 · 아이템 모아보기

인벤토리 구분 없이 아이템 전체를 최신순으로 본다. 내 프로필과 타유저 프로필 양쪽에 있다.

## M-14 · 아이템 상세

주소는 `/items/[itemId]`. **주소에 인벤토리를 넣지 않는다** — 아이템은 짐싸기로 인벤토리를 옮겨 다니는데, 그때마다 주소가 바뀌면 안 된다. 하단 탭이 없다.

위에서부터: 헤더(닫기 × · 제목 "아이템" · ⋮ 메뉴) → 큰 정사각형 사진(칸과 같은 옅은 회색 바탕, 개수가 둘 이상이면 오른쪽 아래에 `× 8`) → 이름 → 설명 → `• 획득일자 26.09.06` · `• 유통기한 26.12.31 까지` (있는 것만) → **같은 인벤토리의 칸들**.

- 닫기(×) → 이 아이템이 들어 있는 인벤토리(M-04)
- **아래의 칸들은 M-04 의 격자와 같은 순서다.** 지금 보고 있는 아이템에는 검은 테두리. 다른 칸을 누르면 그 아이템으로 건너간다. 빈 칸과 + 칸은 그리지 않는다
- **⋮ 메뉴 = 삭제하기 / 수정하기.** 리스트의 밀기 · 그리드의 길게 누르기(M-04)와 같은 일을 한다. 밀기를 모르는 사람이나 마우스를 쓰는 데스크톱에서도 찾을 수 있어야 해서 둘 다 둔다
- 삭제하면 인벤토리(M-04)로 돌아가고, 거기서 지운 자리에 "되돌리기" 칸이 뜬다. 자세한 동작은 M-04 의 "밀어서 수정 · 삭제"
- 피그마의 하트(좋아요)는 2단계에서 붙인다. **북마크는 없다** — 저장이라는 개념이 없고 좋아요 하나뿐이다 (CLAUDE.md)
- 지금은 내 아이템만 열린다. 남의 공개 아이템은 2단계(타유저 프로필)에서 같은 화면으로 연다 — 그때는 ⋮ 메뉴가 없다

## V-01, V-02 · Like 탭

좋아요를 누른 것들이 모이는 탭. 상단이 아이템 / INMYIN 두 갈래.

- 아이콘과 이름은 북마크가 아니라 **하트**
- 검색과 카테고리 필터를 넣는다 (H-01과 같은 방식 — 맨 앞은 항상 전체)
- 좋아요 표시한 아이템은 내 인벤토리에 들어오지 않는다 — 내 것이 아니니까. UI에서 이 구분을 분명히 할 것
