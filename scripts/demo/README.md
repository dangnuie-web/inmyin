# 데모 데이터 넣기 · 지우기

이미지 폴더와 설정 JSON 하나로 데모 유저(계정 · 프로필 · 인벤토리 · 아이템 사진 · 팔로우 · 북마크 · 하트)를 한 번에 넣고, 한 번에 지운다.

**운영 DB 에 쓰는 도구다.** `--yes` 를 붙인 넣기 · 지우기는 당니님 승인 뒤에만 돌린다.

## 명령

| 하는 일 | 명령 | DB |
| --- | --- | --- |
| 마른 실행 — 설정 검사 · 사진 만들어 보기 · 넣을 내용 출력 | `npm run demo -- seed <설정.json> --dry-run` | 안 붙음 |
| 넣기 | `npm run demo -- seed <설정.json> --yes` | 씀 |
| 넣기 + 흰 배경 지우기 | `npm run demo -- seed <설정.json> --yes --cutout` | 씀 |
| 사진까지 다시 올리기 | `... --yes --refresh-images` | 씀 |
| 지우기 미리보기 — 지울 계정 · 줄 수 · 파일 수 | `npm run demo -- clean` | 읽기만 |
| 지우기 | `npm run demo -- clean --yes` | 씀 |
| 시험 (가짜 DB) | `npm run test:demo` | 안 붙음 |

`seed` 에 `--yes` 도 `--dry-run` 도 없으면 마른 실행과 같다. 설정에서 `emailDomain` 을 바꿨다면 지우기에 `--config <설정.json>` 또는 `--domain <도메인>` 을 붙인다.

## 환경 변수 (.env.local)

- `NEXT_PUBLIC_SUPABASE_URL` — 이미 있다
- `SUPABASE_SECRET_KEY` (또는 옛 이름 `SUPABASE_SERVICE_ROLE_KEY`) — 서비스 키. 계정을 만들고, 남의 것을 막는 규칙(RLS)을 넘어 쓰려면 필요하다. Supabase 대시보드 › Project Settings › API Keys 의 secret key. 마른 실행에는 필요 없다

`.env*` 는 `.gitignore` 에 들어 있다. 스크립트는 키 값을 출력하지 않는다(대상 주소의 호스트만 출력).

## 데모 표시

데모 계정은 두 표시를 함께 단다. 지우기는 **둘 다 있는** 계정만 찾는다 — 실제 유저는 건드리지 않는다.

1. 이메일 `demo+<아이디>@demo.inmyin.invalid` (`.invalid` 는 존재할 수 없는 도메인이라 메일이 나가지 않는다. 가입 메일도 보내지 않고 바로 인증된 상태로 만든다)
2. auth 의 `app_metadata.inmyin_demo = true` (서비스 키로만 쓸 수 있는 칸이라 유저가 스스로 붙일 수 없다)

하나만 있는 계정이 보이면 지우지 않고 목록에 따로 알린다. 비밀번호는 무작위로 만들고 어디에도 남기지 않는다 — 데모 계정으로 로그인해야 하면 대시보드에서 바꾼다.

## 다시 돌리면

id 를 이름에서 만든다(아이템 `1-01` → 언제나 같은 id). 그래서 다시 돌려도 중복이 생기지 않는다.

- 계정 · 프로필 · 인벤토리 · 아이템: 있으면 글자(이름 · 설명 · 태그 등)만 갱신. 칸 번호는 그대로
- 사진: 처음 넣을 때만 올림. 바꾸려면 `--refresh-images`
- 팔로우 · 북마크 · 하트: 있으면 건너뜀
- 설정에서 뺀 아이템 · 관계는 DB 에 남는다. 깨끗이 하려면 지우기 → 넣기

## 지우기가 지우는 것

데모 계정과 그것의 프로필 · 인벤토리 · 아이템 · INMYIN 게시물 · 댓글 · 북마크 · 하트 · 팔로우 · 차단 · 알림, 저장소 파일(`items` · `items-raw` · `inventories` · `inventories-raw` · `avatars` · `posts` 의 `<데모 id>/` 폴더), auth 계정.

**실제 유저 쪽에서도 데모를 가리키는 줄은 지운다** — 데모를 팔로우한 줄, 데모 아이템에 누른 북마크 · 하트 · 댓글, 데모가 보낸 알림. 대상이 사라지기 때문이다. 미리보기에 "실제 유저 쪽 줄" 수가 따로 나온다.

앱의 규칙 6(삭제는 `deleted_at`)과 달리 **물리 삭제**다. 데모는 실제 유저의 기록이 아니라서 통째로 걷어낸다.

## 설정 JSON

예시: `scripts/demo/example.json` (유저 2명, 이미지 경로는 가짜).

```jsonc
{
  "imageDir": "~/Desktop/.../inmyin/생성/데모",  // 이미지 경로의 기준. "~/" 는 홈, 상대 경로는 이 JSON 이 있는 폴더 기준
  "emailDomain": "demo.inmyin.invalid",          // 생략 가능
  "users": [
    {
      "no": 1,                       // 유저 번호. 팔로우에서 가리킬 때 쓴다
      "handle": "momo_pouch",        // 아이디. 영어 소문자 · 숫자 · _ 3~30자
      "nickname": "모모",             // 20자까지
      "bio": "소개",
      "avatar": "1_모모/profile*",   // 프로필 사진 (긴 변 320 webp). 없으면 프로필 사진 없이
      "plan": "basic",               // 생략하면 basic (인벤토리 5개 · 25칸)
      "inventories": [
        {
          "key": "pouch",            // 이 유저 안에서 인벤토리를 가리키는 이름. id 를 만드는 데 쓴다 — 바꾸면 새 인벤토리가 된다
          "name": "모모의 파우치",     // 20자까지
          "category": "파우치",       // 고정 8개 중 하나. 아직 DB 칸이 없어 넣지 않는다(로드맵 3단계). 칸이 생기면 채움
          "tags": ["베이스", "립"],    // = inventories.categories. 10개까지, 한 개 10자까지
          "slotCount": 25,           // 칸 수. 생략하면 플랜 값
          "isPublic": true,
          "image": "1_모모/파일.png",  // 인벤토리 사진. 생략하면 첫 아이템 사진
          "items": [                 // 이 순서대로 칸에 들어간다
            {
              "code": "1-01",        // 아이템 번호. 전체에서 겹치면 안 된다. id 를 만드는 데 쓴다
              "name": "메이크업 파우치", // 30자까지
              "description": "설명",  // 필수, 300자까지
              "tag": "케어",          // = items.category. 인벤토리 tags 에 없으면 더한다(앱과 같음)
              "quantity": 1,
              "acquiredNote": "26.09.22", // 획득날짜 칸, 20자까지
              "isPublic": true,
              "image": "1_모모/1-01*",     // 1_모모 폴더에서 이름이 1-01 로 시작하는 사진. 정확한 파일 이름도 됨
              "optional": true,            // (선택) 사진이 없으면 이 아이템은 건너뜀. 필수 아이템은 사진이 없으면 넣기가 멈춤
              "cutout": "1_모모/누끼/....png" // (선택) 직접 딴 누끼 PNG. false 면 --cutout 이어도 배경 그대로
            }
          ]
        }
      ],
      "follows": [2, "juno_desk"],   // 유저 번호 또는 아이디
      "bookmarks": ["2-01"],         // 아이템 번호
      "hearts": ["2-01", "2-02"]
    }
  ]
}
```

설정 검사는 앱 규칙과 같은 한도를 쓴다(`lib/plans.ts` · `lib/item/rules.ts` · `lib/inventory/rules.ts` · DB 제약). 앱 쪽 숫자가 바뀌면 `lib.mjs` 맨 위 상수도 같이 바꾼다.

## 사진

### 파일 찾기

`"폴더/앞글자*"` 는 그 폴더에서 이름이 앞글자로 시작하는 사진(png · jpg · jpeg · webp) **하나**를 찾는다. `1-01*` 은 `1-01_파우치.png` 를 찾고 `1-010.png` 는 아니다. 둘 이상 맞으면 어느 것인지 몰라 "없음"으로 치고 알린다.

- 필수 아이템 사진이 없으면: 마른 실행은 `사진없음` 으로 알리고, 넣기(`--yes`)는 DB 에 붙기 전에 멈춘다
- `optional` 아이템 사진이 없으면: 건너뛰고, 그 아이템을 가리키던 북마크 · 하트도 뺀다
- 프로필 사진이 없으면: 프로필 사진 없이
- 인벤토리 사진이 없으면: 첫 아이템 사진

### 올리는 규칙

앱(`lib/image/upload.ts`)과 같은 규칙으로 올린다.

- 아이템: 썸네일 `items/<유저 id>/<아이템 id>.webp`(긴 변 640) + 원본 `items-raw/<유저 id>/<아이템 id>.webp`(긴 변 1280). `image_url` 은 공개 주소, `raw_image_url` 은 경로
- 인벤토리: `inventories` · `inventories-raw` 에 같은 방식
- 프로필: `avatars/<유저 id>/<사진 내용 해시>.webp`(긴 변 320)
- 화질 0.85 webp. 작은 사진은 키우지 않는다

### 배경 지우기

앱의 배경제거(`@imgly/background-removal`)는 브라우저 안에서만 돌아서 스크립트에서는 쓸 수 없다. 대신 `--cutout` 을 붙이면 **흰 바탕을 지우는 단순한 방법**(`cutout.mjs`)으로 썸네일의 배경을 지운다. 원본은 언제나 그대로다.

- 잘 되는 것: 색 · 무늬가 있는 물건, 검은 물건, 투명한 유리도 대체로
- 안 되는 것: **바탕과 거의 같은 흰 물건**(흰 이어폰 케이스 등) — 몸통이 같이 지워질 수 있다. 이런 아이템은 `"cutout": false` 로 빼거나, 직접 딴 누끼 PNG 를 `"cutout": "<경로>"` 로 준다
- 옅은 그림자 일부가 남을 수 있다

`--cutout` 없이 넣으면 앱에서 배경제거를 누르지 않은 아이템과 같다(흰 배경 그대로).
